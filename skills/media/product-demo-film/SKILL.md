# Product Demo Film from Design PDFs or a Live App

End-to-end pipeline: screens (design-source PDFs, or Playwright captures of the deployed app) → rendered MP4 with motion, music, SFX. The framework contracts live in the `hyperframes-core` / `hyperframes-cli` skills (external, read-only); this skill is the orchestration order and the pitfalls they don't cover.

## Scope rule (user's chosen base cut)

When the user names a specific delivered version as the winner ("I like THIS better … just update the X of this, thats the only thing you do"), it is the immutable base: rebuild ONLY the named aspect, keep timeline/structure/audio byte-identical where possible, and drop every superseded instruction from earlier variants (pacing notes, alternate cuts, rejected deliveries). Never re-deliver a rejected variant, and never widen the scope to "fix" what the winning cut already has.

## Role-context rule (navbar identity)

The visible bottom navbar is part of a frame's identity: **Role → Navbar → Page → Function → Narration must all agree.** Before using any page as a walkthrough shot, classify it by navbar (patient portal / doctor 4-tab / owner 6-tab) from the text layer — many PDFs contain the SAME screen in two role variants (e.g. calendar, patients list, messages inbox), and picking the sibling with the wrong navbar is the classic sync bug. Never use a doctor-context frame under patient narration or vice versa; a patient-side inbox/thread page exists in the PDF — find it (`pdftotext` grep for the patient greeting/portal strings) instead of reusing the doctor's.

Highlights must agree with the SAME rule: a navbar-tap highlight rect measured on one role variant's navbar lands on empty space or the wrong tab when the shot renders the other variant — re-measure per page, never share a nav rect across variants.

## Procedure

1. **Read every source PDF before building.** `pdftotext "<file>.pdf" -` each one. Map screen pages to story beats (patient flow / clinic flow / owner flow), and pull pitch-deck + cost-benefit numbers.
   - Counters and ROI cards must quote the deck verbatim — never invent or round metrics. Cross-check UI analytics screens against deck claims; if they agree, the numbers are safe to animate.
   - Vision-audit flags on screen crops (odd service names, typos) are usually IN the source design — verify against the PDF text before "fixing" them.

2. **Get the screens — honor the source the user names.** First confirm WHICH deploy is the client's product: get the exact URL and the brand name the client actually uses before capturing anything — sibling/student projects on one hosting account look alike, and client-chosen names override internal project names. Building against the wrong deploy wastes a full capture pass. Then: Design PDFs OR the deployed app: when they say "browser/deployed version" (or the app is live and the designs are stale), capture the live app (see "Screens from a live deployed app") and never fall back to design frames for a rebuild they scoped to the live product. From PDFs: `scripts/extract_screens.py <pdf> <outdir> <pages...>` (pdftoppm 300 dpi → white-diff bbox crop → normalized names). 300 dpi ≈ 1625px-wide phones: crisp at 1080p zoom. Composition `src` attributes must match filenames exactly — lint fails on mismatch. New pages extracted AFTER a build must be re-copied into the project (whole-tree copy runs at build time, so rebuild the composition, don't hand-copy).

3. **Probe the pipeline.** `command -v ffmpeg`; `npx hyperframes --version`. If npx fails silently (exit 1, no output): `npm init -y && npm i hyperframes` in the workspace and use the local binary — don't debug npx, install local.

4. **Pick format.** Phone-app walkthrough demo → portrait 1080×1920. Pitch/launch film ("Apple-style") → landscape 1920×1080.

5. **Layout beats BEFORE generating audio.** One generator script is the single source of truth: beats as `(dur, kind, payload)` tuples, `assert abs(sum - TOTAL) < 0.01`, emits `timeline.json` + HTML.
   - Section the film: problem → reveal → feature flows → analytics counters → ROI cards → montage → final. Anchor music structure (drums in, build, riser+impact, peak, resolve) to beat boundaries.
   - Bake BGM impacts at the ACTUAL montage cut points from timeline.json. Any beat retiming → regenerate BGM; stale impacts land between cuts.
   - The SFX whoosh/boom/bell cut list must derive from the timeline section budgets, never a duplicated hardcoded tuple — it desynced twice (whooshes played at the PREVIOUS version's act cuts after retiming). Verify with an sfx.wav envelope peak scan: peaks must sit ~0.15s before each section cut (whoosh starts at cut-0.45, .6s window).
   - False-defect loop: asking vision to confirm an ASSUMED element ("where is the callout that should draw?") manufactures phantom defects on by-design-plain shots (a 2.3x macro has no callout by design). Ask neutrally "what is present?".
   - `render_all.py` caches per-seg, but every build rmtree's the project dir (segs die with it). Audio-only fix: back up segs/ + frames/, build, restore, then render_all cache-skips all segs and just remuxes (seconds, not a 35-min re-render).
   - **CUES list order must match SHOT order.** Index-keyed TTS caches (cue_XX.mp3) silently mismatch after reordering — purge the cache directory on ANY cue/shot reorder. An edit that inserts cue text into the wrong list position produces absurd overflow errors downstream; fix the order, not the symptom.
   - Recap/outro narration spanning several beats belongs to ONE shot with multiple cues — never clone near-identical shots to stretch it (duplicated frames fail 'no duplicated scenes' review checks).
   - Reordering/renaming shots touches MULTIPLE dicts (SHOT_ORDER, MINDUR, CUES, SFX list, QA page sets). After such an edit, run a name-set diff (labels in CUES ⊆ SHOT_ORDER, no empty-string labels) before rebuilding — partial edits surface as KeyErrors mid-build.

6. **Audio.** Synth BGM + SFX with `scripts/bgm_sfx_gen.py` (numpy+wave; technique per `media/python-audio-synthesis`). Bake BGM gain (~0.25) so SFX/VO stay hot. Voice (optional): Fish Audio `/v1/tts` with `reference_id` if the key has API credit — HTTP 402 means API credit exhausted (billed separately from platform credit; check before planning a voiced video). Fallback: edge-tts — synth ONE test line per voice before batch; a dead voice fails with `NoAudioReceived` (en-PH-RosaNeural verified working, en-PH-NeomiNeural dead). Pass rate/pitch in joined form (`--rate=-2%`) — a separate argv `-2%` is parsed as an unknown flag and the CLI dies printing usage.
   - **BGM busyness ceiling:** pads + one soft bell per downbeat + light drums (doctor/owner sections only) is the approved ceiling. Extra motion layers (16th-note arps, shakers, 9th-extended chords, BPM lifts) read as 'distracting and annoying' under narration — add NOTHING that plays more than ~2 events per beat. Duck to ≤0.26 under cues and keep BGM RMS well under VO RMS (verify: bgm under-VO RMS ≈ VO/10 or lower).
   - Narration must not make absolute product claims ('no cash handling', 'fully automatic') unless the UI proves them — prefer scoped benefit wording ('cutting down front-desk handling for every appointment'). Verify each edited line against the screen shown at that moment before rendering.

7. **Build the composition.**
   - ≤ ~15 scenes and light CSS: one mono `index.html` is fine.
   - Bigger, or many radial-gradients/filters/blur/backdrop-filter: **one sub-composition file per beat**. Mono builds with ~40+ heavy-overlay elements are a known capture-layer bug (solid-black first half of render). Host carries: shared `.hostbg` full-length background clip (track 1), ALL `<audio>` elements (bgm + sfx, tracks 9/10), and GSAP in host `<head>` — sub-comp scripts run in host context.
   - Sub-comp contract per hyperframes-core: everything inside `<template>`, root styled by `#root` not a class, host `data-composition-id` == inner id == `__timelines` key, `fromTo` (never `from`), beat-LOCAL times inside each sub-comp.
   - Feature beats follow **establish → focus → act → result**: the camera pushes toward the element being narrated, THEN the cursor acts. Make the camera tween's transformOrigin the highlight rect's own center so zoom and box cannot drift apart. **Camera zoom levels are user-tasted (rejected twice):** Attila rejects any zoom that crops the phone out — 1.24-1.34x reads as a "botched crop" (bezel clipping) and 2.8-3.4x macros read as "super zoomed in". Accepted grammar: gentle 1.02-1.18 full-phone shots + highlight boxes for detail emphasis, plus AT MOST ONE deliberate macro (2.2-2.4x) per film on the single money moment the caption names. Never a macro flash sequence. Frame-level context (feature caption, role pill) mounted outside the camera adds visual hierarchy without touching the UI. Same-page continuations (navbar taps, scroll follow-ups) use a short fade; new pages rise in.

8. **QA loop — gate is 0 errors.** `lint` → `check` (runtime+layout+motion+contrast in one browser pass) → `snapshot --at` midpoints → contact-sheet vision audit → fix → re-check.
   - The layout gate samples real frames: a callout that clears its caption statically can still overlap mid-pan. Re-run check after any position change.
   - Contact-sheet audit catches what lint can't: wrong-screen reuse, text clipped by the device bezel, unstyled corners. Stamp row/col IDs on every cell and ask vision for findings named by row+column with the exact fix — then re-review until the verdict is "ship"; "close" is not done.
   - Counters/typewriters caught mid-animation in snapshots show intermediate values — verify the target value in code, not the snapshot.
   - **AI-auditor findings need per-claim verification before editing.** Free vision models (qwen-omni, glm) over-report: cross-check each defect claim against `pdftotext -bbox` word boxes / pixel scans; expect roughly half false positives (reading the phone bezel as 'overflow', PDF's own layout as 'overlap'). The real catches are worth it — a strict-but-lying model found six genuine rect defects one pass. Use multiple auditors (local free models via opencode + xKiro vision) and triangulate — invocations in `references/ai-auditor-providers.md`.
   - **Scan scene boundaries for black flashes.** A 1-frame luminance dip at a clip boundary (crossfade gap) reads as flicker on big screens. Extract ±0.05s frames at every shot start and flag luminance <30; fix structurally by having each scene paint its stage instantly (background first frame, phone animates in inside it — no root fade-in). An intentional dark stage card is not a flash: flashes are lone dips between two bright frames.
   - Frame extraction for verification must use accurate seek (`-i file -ss t`) — fast keyframe seek (`-ss` before `-i`) grabs a neighboring scene at boundaries and fabricates phantom 'dark frame' / wrong-screen findings.
   - Client/team-reported timestamps are approximate and reference whatever build they watched — locate each reported issue by its described CONTENT in the current timeline (find the shot whose screen matches the description), never by the literal timestamp.
   - **After one or more fixes a client still judges broken: AUDIT-FIRST, no more edits.** Run a diagnosis-only pass (extract frames, stamp each cell with the active VO line from timeline.json, vision-check narration-vs-screen) and deliver a timestamped frame-vs-narration table plus an explicit correction map (current → problem → correct frame → required narration) for approval. Then fix ONLY the mapped items — partial fixes after repeated failure erode trust faster than the original defect.
   - Targeted-revision briefs (client lists N defects): change ONLY the named items and prove it — diff the generator against the prior version before rebuilding; every unedited byte of the previous build stays put.
   - Vision on large contact sheets times out (420s) — split sheets ≤8 cells, and fall back to pixel-stat (amber-pixel bounding boxes per frame) for highlight-alignment checks.

9. **Render + verify + deliver.** `render --quality high --output out/<name>.mp4`; verify `ffprobe` duration/streams + `volumedetect` (no clipping); extract 2–3 spot frames and vision-check; copy to `~/Downloads/<Name>.mp4` (user's standing delivery location). When asked for a NEW independent version, build in a fresh project dir with version-suffixed generator scripts and a new output filename; treat every prior delivered file as read-only reference and verify its checksum is unchanged after your work.
   - Music-free variant of an already-mixed master: rebuild the VO/SFX stems at the same trim/start offsets, amix them, then mux with `-c:v copy` — lossless picture, identical duration. Never re-render the video for an audio-only change; verify the remuxed audio with `volumedetect` and the video stream with a checksum of extracted frames.
   - **Picture-only revision of an approved cut** (screen swap / re-cut, mix unchanged): stream-copy the approved master's audio into the new picture (`ffmpeg -i new.mp4 -i approved.mp4 -map 0:v -map 1:a -c copy`) and verify audio-stream checksum parity across versions, so a picture revision can never drift the mix. Cache per-scene segment renders (keyed by scene id + duration + fps): a flaky or edited scene re-renders alone, then concat + mux, instead of re-rendering the whole film.

## Screens from a live deployed app (Playwright)

When the film must show the REAL product, capture the deployed app with Playwright instead of extracting PDF pages. Shoot the CURRENT local build (dev server at the pinned repo HEAD) whenever the deployed build is stale or the brief demands up-to-date UI — an outdated UI is the first thing the user or panel calls out; record which commit the footage came from. Same downstream contract: PNGs at the design assets' pixel size, plus a rect JSON in the same schema. The scene generator then takes a screens-dir override and a rects-JSON override; swap BOTH together around the build (one build script that trades the JSONs around the generator run and restores the design ones after keeps the design export authoritative for other variants).

1. **Match the design asset geometry.** Capture at the design frame's pixel size (mobile viewport 390×844 scaled to asset width, e.g. deviceScaleFactor 4.167 → 1625px-wide PNGs) and reuse the asset filenames, so scene geometry and box math carry over untouched.
2. **Scope every selector to the visible UI.** Responsive apps keep hidden desktop chrome (sidebars, duplicate navs) in the DOM; bare selectors match those first and Playwright waits time out on invisible nodes. Append `:visible` / `.filter(visible=...)` to every locator.
3. **Verify state after every click.** A successful click is not a state change: disabled handlers and swallowed API errors (e.g. a 409 the app never surfaces) no-op silently. Assert the resulting state (selected class, enabled button, visible confirmation text) before shooting.
4. **One transactional flow = one capture session.** Shoot the whole chain (browse → form → confirm → payment → success) per attempt and overwrite the shots each attempt, so every frame shares one date/amount state. Shots assembled from different attempts read as continuity bugs. Loop deterministic candidates (free date/slot) with re-verification instead of debugging the app's constraints: hard constraints (one-record-per-day uniques, booking windows) may count expired rows.
5. **Success screens that only exist after a real transaction:** complete exactly ONE end-to-end transaction in the provider's TEST mode and offer to clean up the created rows; all other forms get typed but never submitted. When the confirmation step lives on the provider's site and its URL is server-side only, read the URL via service-role DB access, drive the provider's test authorize page in a second browser while the capture session polls the app, and verify the end state in the DB before shooting the success screen.
6. **Re-measure highlight rects from the live DOM**, never trust the design JSON: `getBoundingClientRect()` → normalize to the screen image as `{x,y,w,h,cx,cy}` %-rects in the existing callouts schema. Live layout spacing differs from the export, so a design-measured rect lands on the wrong element; fall back to the design value only where the live element cannot be located.
7. **Viewport-only screenshots** (`full_page` explodes on tall hidden containers) and keep the capture store OUTSIDE the generator's project dir (see Pitfalls: generator wipe radius).
8. **SPA routing reality: deep URLs may 404 on static hosts without rewrites** — navigate by clicking in-app links and treat `goto` as unproven until tested. Role-switcher flows (demo menus that swap persona) leave an onboarding/welcome modal up that silently no-ops every later click: after a switch, click its Continue/dismiss and assert the overlay is gone before the next navigation.
9. **Measure highlight boxes against normalized `innerText`, never `textContent`** — CSS `text-transform: uppercase` leaves the DOM source title-case and curly apostrophes break naive `includes()`. Normalize both sides (lowercase + fold quote variants). Pick the target as the smallest element whose box area is ≥ ~1.2% of the viewport (row/card, not a micro-span inside it) **and whose rect intersects the viewport** — smallest-match alone grabs an off-screen lookalike elsewhere in the DOM (hidden duplicates, below-the-fold copies) and the camera then pans to a poison %-rect (e.g. y=384%), making per-frame screenshot cost explode near the shot's end until the render stalls. Sanity-assert every box center (cx, cy) ∈ [−1, 101] before writing the JSON. Re-measure until every rect resolves; a MISS usually means the anchor string is stale demo data — verify each anchor against the fresh screenshot and re-point it to equivalent text that is present, never relax the filter to force a resolve.
10. **Reel names, filenames, and timeline sheets are hypotheses — verify every capture window's role from the frame itself** (portal subtitle, sidebar, header) before it enters an edit. Recordings routinely open on a different role's screen than the file suggests, and two same-looking windows presented as different worlds (duplicate homes flashed as "three worlds" in a hook) is the classic failure. Extract the first frame of each window and classify it before building the cut list.

## Short montage variant (sizzle re-edit)

When asked to re-cut a long demo into a short montage ("too long, it should be a montage"): build a NEW curated timeline from the strongest moments — never speed-ramp the existing cut. Narration drops entirely; labels + visuals carry the story.

1. **Beat-lock every cut.** Choose BPM so the beat grid is 0.5s (120 BPM) and place every scene start ON a beat; the cut list is then synchronized to the music by construction and cannot drift. SFX whooshes on section cuts only.
2. **Structure:** ~3s brand hook (name + positioning line + 1–2 strongest-screen flashes) → design the brand card FRESH per client (new wordmark motion, new idea for the name) — never recycle a previous film's design language into a new client's film. one section per user role in product-usage order (divider card → workflow moments, fast cuts) → final feature flash (~1s cuts of the strongest screens) → close card (brand + one-line positioning, fade to black). Shots: content shots sit on VERIFIED READABLE HOLDS of 1.6–2.6s (heroes 2–3s); 1.0–1.5s is legal only inside a deliberate rapid/flash block and hook flashes floor at 1.0s. Total is content-driven inside the 30–60s guideline — never stretch or trim to hit a stopwatch number. **Comprehension gate: "short does not mean rushed"** — if a first-time viewer cannot name the screen and the action from a shot, lengthen it. "CUT HARD" removes dead time and weak shots, never readable time. When feedback says "too fast / the user will not understand," the fix is longer holds and fewer cuts — more polish on unparseable shots does not help.
3. **Labels replace narration:** per shot a small kicker + name (2–4 words) plus a role pill. The pill must obey the role-context rule. A role that plays two sub-roles (e.g. clinician + manager) gets BOTH staged explicitly in its section — clinical moments first, management second — and the label names the duality.
4. **Motion vocabulary is mandatory — fade-and-cut alone is rejected as boring.** A montage of the same centered phone fading in and out reads flat however good the screens are. Every shot must move differently from its neighbor: phones slide in (OPAQUE) with entry directions rotating right → left → bottom → top down the cut list, captions slide in with an overshoot, role titles whip in skewed, divider cards ken-burns, camera zooms kept — detail pushes have only two legal scales: gentle 1.02–1.18 with the device mockup fully intact, or a true macro 2.2–3.2 full-bleed crop of one detail. The 1.3–2.0 dead zone clips the mockup mid-bezel and reads as a botched crop. Entries only — never exit tweens at a hard cut (Pitfalls: hard-cut boundary blink). Kill the "screens popping in and out" verdict with LAYERED motion per shot: (a) entry GATED BY SHOT LENGTH (v9 "feels weird" loop: the same entry on every cut is a metronome — 9 identical slide+bounce arrivals in a row reads mechanical): d≥2.25 slide-in (`power3.out`, no `back.out` overshoot), d=2.0–2.25 scale-pop .94→1 `power2.out`, d<2.0 HARD CUT (no entry tween at all — the cut is the transition; drift/cursor/callout carry the in-shot motion), (b) full-duration phone drift AFTER the enter (`sine.inOut` to ±100px gentle / ±24px at macros — amplitude must scale DOWN with camera zoom or the macro target sweeps out of frame), (c) callout boxes DRAW ON (`scaleX:.15→1`, `transformOrigin:'left center'`) instead of sitting as static stickers, (d) captions letter-stagger in as slide-fade (yPercent 60 + autoAlpha, stagger .026) — NO overflow:hidden reveal mask (see Pitfalls), (e) in-screen events on 3–5 shots (cursor tap at the callout rect center + click ring, toast) so something happens INSIDE the screens, not just to them. Motion-delta ground truth: mean abs frame diff early-vs-settled within one shot should be >10 (a frozen tail = the cam tween ended mid-scene — set cam dur ≈ scene dur).
5. **QA deltas:** boundary-blink scan at EVERY cut boundary (flag frames at background-only luminance, ~<35); screen identity + labels + pill verified by vision on single extracted frames at shot midpoints; motion travel verified numerically (feature pixel extents across frames) since fast eases read as static in stills; runtime and loudness via ffprobe.

6. **Tightening when the edit is called "too long"** — a duration defect, not a taste call. Priority: story/clarity > pacing > shot selection > UI visibility > transitions > audio > typography > polish. Map every timeline row to its source screen first, then cut in this order: verbatim duplicate screens within one act (a macro re-use is legitimate only when it crops a visibly different region) → low-information beats → re-frame surviving second beats as macro detail inserts instead of full shots. Keep totals on the beat grid (2.0 s bars @ 120 BPM) and move every hardcoded cue with the cuts.

Deep recipe + brief checklist: `references/montage-sizzle.md`. Real-footage variant (Playwright screen-recording recut → EDL → per-shot crop/encode → sections + xfade): `references/footage-recut.md`.
   - The output file may not exist for a minute after 'Render complete' (assembly continues) — poll ffprobe before QA extraction, else ffmpeg exits 254.
   - Delivered-video verification must sample frames at the CURRENT timeline JSON's shot starts, not stale printed timestamps — after any reflow the old midpoints land in crossfades and produce phantom mismatches.

## Pitfalls

- **Hard cuts take entries only, never exits.** An exit tween (slide-out/fade-out) paired with an entry that starts transparent empties BOTH sides of the cut, and the boundary frames show bare background — a visible blink even at 30fps. Author entries opaque (position slide-in with autoAlpha 1 from the clip's first visible frame) and let the outgoing clip hold its last frame; then scan every cut boundary for frames at background-only luminance, not just lone dips between bright frames.
- GSAP: never tween `left`/`top` or `letterSpacing` — lint errors (pixel-snap under seek-by-frame capture). Use `x`/`y` transforms; hold letterSpacing statically.
- `<audio>` clips need an `id` or the renderer drops them silently.
- Animated counters: tween a proxy object `tl.to({v:0},{v:N,onUpdate:...})` and scope the DOM lookup per composition (`document.querySelector('[data-composition-id="X"] .cls')`). `this.targets()[0]` is undefined at construction time, and unscoped class selectors hit sibling scenes' elements.
- Delete or rename old compositions out of the project (`index-v1.html`, `.bak`) — multiple roots with `data-composition-id` cause duplicate-discovery errors and double audio.
- Regex-rename page images (`pNNN-NNN.png` → `pNNN.png`) before wiring `src` attributes — the pdftoppm suffix pattern will not match hand-written asset paths.
- Cursor/highlight overlays move in px transforms relative to the phone screen box — compute positions from the screen's inner size, not percentages of the frame.
- **Never tween zoom/scroll on the page image inside a phone screen.** The screen box crops it: headers/bottom-navs vanish mid-push-in, and pages whose extracted height ≈3517px @1625w (a 390×844pt PDF page) have ZERO scroll slack — any scroll exposes a white gap (screens get clipped by 2× viewport). Wrap the phone in a `.camera` absolute-inset wrapper (stage has huge margins) and tween the camera's scale/transformOrigin instead; leave the screen content untouched. Vision QA on spot frames is the only way to catch this — check/lint pass regardless.
- **Audio-driven timeline beats hand timestamps:** synth all VO cues first, measure with ffprobe, then iterate shot durations (expand cued shots to fit their cues +0.45s tail, compress cue-less HOLD shots to keep total) until zero overflows. Emit timeline.json as the single source for composition, BGM sections, and SFX cues.
- edge-tts voices verified 2026-09-21: OK = en-US-AndrewNeural, en-US-GuyNeural, en-PH-RosaNeural, en-AU-NatashaNeural, en-US-BrianNeural; DEAD = en-PH-AdamNeural, en-PH-PesiNeural, en-MY-YasminNeural. Always 1-line test before batch.
- `check` on 100+ sub-compositions takes ~30–40 min — run it backgrounded with notification. `snapshot` batches >4 points can crash the browser (Target closed) — batch ≤4 and retry the rest.
- **Callout rects must be MEASURED, never guessed**: `pdftotext -bbox` per page → map pdf-pt → cropped-asset CSS% (crop offset = white-diff bbox of the 300dpi render / (cb[2]-cb[0])). Match with EXACT token equality; digit keys need boundary regex or `26` matches `2026` and `1:00` matches `11:00`; single-word keys must NOT line-extend. Text-run boxes need container growth for row/card targets. Never teal-on-teal for highlight rects (invisible on buttons) — use amber #d97706. A clipped dialog INSIDE the source PDF cannot be fixed by re-render — swap the page.
- **Rect keys are page-bound, not shot-bound.** When a shot's asset page changes (role-variant swap), every rect key it references must be re-measured on the NEW page — navbar tab positions differ by ~13% between role variants, and a stale key silently highlights the wrong element. Audit pass: for each nav-highlight key, assert the rect encloses the target word's bbox from that page's own bbox HTML.
- Vision QA frames taken mid-shot catch sequential staggered highlights — for paired targets, start both boxes at the same time. Pixel-stat fallback (mean luminance + per-channel spread + ink%) screens 28 spot frames in 5s when the vision provider is saturated; crops disambiguate light-theme frames. For highlight alignment specifically: detect amber pixels inside the phone crop and compare the x-span against the target word bbox — decisive where vision models disagree.
- **Overlay chips/toasts must sit OUTSIDE the camera wrapper.** Anything inside the phone screen gets cropped under camera zoom (phone screens are ~987 css px tall; zoom ≥1.1 pushes the bottom past the 1080 frame). Mount them as siblings of `.camera` at fixed frame positions and zoom can never clip them at any level — capping zoom ≤1.08 or lifting overlays mid-screen are weaker workarounds only. Verify with one snapshot before rendering.
- When a client sends a REVISED design PDF, re-derive page numbers from the text layer — page indices shift between exports (SF Dental 1→2 moved every patient page) and removed flows vanish entirely. Measure callout targets per page from the NEW pdf; a rect measured on the old export lands wrong on the new one.
- **Darkened-modal frames are unusable as walkthrough shots.** Figma exports often show a page in its modal state (Log Out / Edit-note dialogs with a gray scrim, ~90% mid-gray pixels). Detect cheaply: mid-gray (L 90–190) pixel share — >50% = scrimmed; swap to the clean sibling state. Multi-screen boards (single wide PDF page with several phones) yield extra screens: render the board, find phone panels via content-column runs, white-diff-crop each into its own asset, then measure callouts in board coordinates and convert to panel-relative % — subtract EVERY crop level between PDF and asset (board white-diff crop origin AND panel crop origin); one missing level silently offsets the rect.
- Empirical rect anchoring beats math across double crops: after placing a highlight, snapshot the frame, detect BOTH the amber box and the target (e.g. filled-teal rows) in frame coordinates, and iterate the asset-% rect until the box fully encloses the target. One or two iterations converge.
- **Rect dict edits must load-modify-save in ONE cell.** Editing `callouts.json` across multiple execute_code cells loses earlier edits (each cell re-loads the file fresh) — apply all rect changes in a single load→modify→dump, then verify by re-reading the file. A lost rect edit silently renders the OLD highlight and burns a whole render cycle to discover.
- **Transcript-verify edited narration** (faster-whisper small/int8 on the rendered audio window) — it catches stale-TTS-cache mismatches and timing slips that code review misses. Whisper word timestamps also give precise voice-vs-screen timing evidence when a client reports sync issues.
- **BGM loudness is not the same as busyness.** Lowering gain does not fix 'annoying' — remove motion layers (arps/shakers/extra notes per beat) first, then adjust gain. Calm ≠ boring for corporate demo beds: pads + downbeat bell + light drums reads professional.
- Long raw ffmpeg encodes: prefer a FOREGROUND terminal with a generous timeout (600s+) — backgrounded raw ffmpeg has died silently mid-render often enough to be a rule; if it must background, verify the output with ffprobe before trusting it. HyperFrames `render`/`check` may run backgrounded with output logged to a file: poll the log for its completion marker in bounded waits, then verify with ffprobe — but never trust a backgrounded run without a marker + output check. Note `render` takes the project DIRECTORY (`render .`), and `--rate` is an edge-tts flag only (render rejects it).
- **Reuse a generator's templates for a variant build by exec'ing its source up to a build marker into a namespace dict**, then override the dict's data entries (SHOTS/CAPS/labels) — template functions share that dict as `__globals__`, so their output changes without touching the template code. Never `import` such a generator: its module-level build runs on import and can wipe/rebuild the project dir. Per-scene visual tweaks in a variant (motion, title entrances) need no template edits at all: string-surgery the generated HTML, anchoring each injection on `window.__timelines["<cid>"] = tl;` (add tweens just before that line / replace its known entrance tween), and grep-verify every injection landed before rendering — a silently missed anchor ships the old motion.
- **Screen identity is decided by vision on single frames, not pixel correlation.** Downscaled grayscale/gradient comparators false-FAIL on similar app screens, and auto-bbox targets get polluted by white caption text. Extract a frame at the shot midpoint and ask vision 'what does the screen show + what do the labels say' — decisive for identity, pills, and label rendering; use pixel scans only for black flashes and fade endpoints. Still-frame audits flag mid-animation cursor/ring states as misplaced highlights — verify with pixel extents before 'fixing' one. The converse also bites: a frame sampled mid-scene on a fast ease (power3.out ≈ 78% settled at 40% of its duration) reads as static and can false-fail a motion check — vision will call a mid-motion title 'settled'. Sample within the first ~20% of the ease, or track the moving feature's pixel extents across 3–5 frames as ground truth. To verify a highlight rect's placement, draw the rect on the SOURCE screenshot and vision-check what it encloses; under `object-fit:cover` a source taller than the screen box shows only its top fraction, so map % first: visible fraction f = box_h·img_w/(box_w·img_h), source_y% = box_y%·f.
- **A generator that rebuilds its project dir on every run makes that dir SCRATCH.** Re-running such a build destroys captures, helper scripts, and deliverables kept inside. Inventory the dir before the first build and keep everything durable outside the wipe radius, or restore it after every build.
- **Before re-running any build/render chain, grep its OUTPUT PATH.** A hardcoded output filename in a render script silently overwrites the previous deliverable at assembly time — or ships the refreshed build under a stale version label when the deliverable of record kept its name. Give each new version its own filename, copy every prior deliverable into a preserved dir BEFORE the first build (the project-dir wipe takes `out/` copies with it), and verify prior checksums are unchanged after the run. Helper scripts copied into the project dir must resolve their data root by existence check (`compositions/` beside `__file__`, else `parent/<dir>`), not a fixed relative join — the same master invoked from the project root and from inside the project dir otherwise doubles the path.
- **Rebuilding an existing film under a new brand: splice, don't rewrite.** Keep scene ids, start times, and durations byte-identical (the synthesized audio bed is deterministic and beat-locked to them) and swap only content/brand. Generate the splice as a script with assertions (ast.parse + expected-string counts) instead of hand-editing, and emit embedded newlines in generated literals via `chr(10).join` — backslash escaping is where a code-emitting generator silently turns real newlines into literal `\n` text.
- **`pkill -f <script>` matches the wrapping shell's own command line** and kills your session mid-remediation. Kill by exact PID from `pgrep -af` output, then confirm with a follow-up `pgrep`.
- **A timeline edit moves the whole cue sheet.** Hardcoded SFX/whoosh times, beat-grid hashes, and any downstream script that parses the generator asserting the old TOTAL must all be realigned with the new cut points — grep for the old numbers before rebuilding.
- **Silent-caption montages are a different class.** Fast-cut, beat-driven showcase with on-screen captions and no narration → `product-montage`; its `references/render-pipeline.md` carries the shared composition op semantics (`hl` visible-window vs draw time, `cam`/`focus` travel times, toast auto-fades) and the segment-cache recipe for cheap partial re-renders.
- **Vision contact sheets are inventory-only.** Vision misreads thin callout boxes at sheet scale and hallucinates content absent from the frame — never edit from a sheet judgment; crop-verify at full res first.
- **Caption layer over macros: white text on white UI reads as "clipped/missing captions".** At true macro zooms the screen fills the frame and any white caption dissolves into it (vision reports 'only top half of glyphs visible' — it is white-on-white, not clipping). Give caption chips a solid scrim (rgba(2,10,18,.64), NO backdrop-filter: blur + low alpha let UI dividers bleed through glyphs and a line through a price glyph reads as struck-through). Letter-stagger reveals must NOT clip: `overflow:hidden` letter boxes cut the deeper descenders (g loops, ₱ stems) flat at ANY line-height that satisfied shallower ones (y) — use an unclipped slide-fade reveal instead. And the peso sign ₱ naturally carries two horizontal bars: vision models reliably misread them as a "strike-through artifact" at small crops — confirm at 3x zoom before touching typography.
- **QA frame timing splits by what you verify: settled framing vs motion.** Framing/crop checks need the shot's SETTLED frame (scene_end − 0.15s: the zoom has landed and macro crops read as true macros); motion checks need early frames (<20% into the ease). Sampling a macro mid-zoom (t+0.3–0.5 of a 2s shot) makes every macro look "under-committed / still whole-phone" and burns fix rounds on non-defects. A 2.5x zoom on a ~500px-wide phone mockup is NOT a macro (sides still visible): true full-bleed needs 3.0–3.4x, which 1625px-wide screen rasters support at native resolution.
- **A montage build can hide a failed callout key behind a stale segment.** Always check the build's exit code AND the composition count against the expected scene count after a timeline change; validate every callout key against the analysis JSON and every fx op against the template contract (`focus()` returns a list of ops → bare `fx=`; `hl()`/`cam()` return single ops → `fx=[...]`) before building.
- **The montage T table is (label, kind, START, DURATION, ...) — TWO timing columns.** Retime BOTH: editing starts without durations desyncs render_all's per-scene frame counts or silently renders wrong-length segs. render_all.py asserts start == running sum of durations — keep that assert when porting.
- **A build does NOT wipe `segs/`.** After touching comps always `rm segs/*.mp4 frames/seg_*` before a full render, or render_all silently reuses stale cached segs.
- **Per-frame seek+screenshot loops HANG, they don't fail.** The frame loop (`window.__tl.time(t)` via `page.evaluate` + `page.screenshot`) has no timeout: a runaway transform (e.g. a poisoned camera target) makes each screenshot progressively slower until the loop stalls silently with no error, and retry-on-failure logic never fires. Bound every render attempt with an outer `timeout N` in a loop of attempts that resume from the cached segs, log to a file (never a pipe), and treat a finished run with no output file on disk as a dead run, not a done one.
- **Shot-rhythm monotony reads as "feels weird" even when every shot is individually polished.** A run of equal durations (9×1.5s) is a metronome; mix a rhythm curve (heroes 2.5–3.5s, connective 1.0–1.5s, deliberate staccato bursts allowed as bursts) and make animations LAND before the cut: letter-stagger captions on <2.0s shots go instant (stagger 0), entry tweens skipped entirely on short shots.
- **Vision false-positive class: thin highlight-box borders at thumbnail scale.** Grid cells <600px wide make a 3px amber box read as "half-drawn / open edge". Before "fixing", extract a time-triple (t−0.3 / t / t+0.3) at full res: constant shape + opacity change = fade (fine), shape change = real mid-draw freeze.
- **Crop boxes must match the output aspect.** A crop window whose w:h differs from the render aspect is stretched flat by the scale step (a 2.8:1 box scaled to 16:9 = squished UI); measure crops on real frames and re-verify element proportions in the per-shot QA before assembling.
- **When file state contradicts your recollection of what you wrote, believe the disk.** Memory of generated content is reconstructive; a plausible "someone else rewrote my file" theory costs a debugging detour. Resolve identity from stat + content (docstrings, anchors) before diagnosing external interference.
