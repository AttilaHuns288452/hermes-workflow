# HTML Prototype Build & Verify

Class: produce a self-contained HTML prototype/artifact from a brief (spec, proposal, feature list) and verify it actually works before delivering. For design doctrine (taste, anti-slop, composition) load `frontend-design` and `creative/claude-design` alongside — this skill is the engineering loop those skills assume.

## Procedure

1. **Inventory the brief.** Extract every feature into a checklist row (feature → where it lives in the UI). Anything with both a user side and an admin side gets both. Nothing from the brief is silently dropped; nothing not in the brief is invented (prototype = visual contract, demo data is expected to be fake and made-up). An enumerated feedback doc layered on the brief (panel suggestions, meeting changes, review comments) is a second spec — its items get the coverage audit below, not a best-effort pass.
2. **Commit to an information architecture.** One top nav, one view per major feature group, modals for create/review/detail actions, demo data as a single flat JS array at the top of the script. Pick a palette and type scale up front (CSS variables); no framework, no CDN dependencies.
3. **Author in appended chunks.** For anything above ~15KB, write the first chunk with write_file, then append remaining chunks via execute_code (read file → `content + chunk` → write). Verify `"appended chunk N, total: X chars"` after each append. Tail markers (`</script>`, `</body>`, `</html>`) land in the final chunk.
4. **Syntax gate — before any browser test.** Extract every inline `<script>` block and run `node --check` on the concatenation. Fix until clean. The gate catches what rendered pages hide. Re-run the gate after EVERY scripted edit batch to the file: an inserted quote inside a string-concatenation line closes the literal early, and the artifact may still render.
5. **Serve and click through.** `python3 -m http.server <port> --bind 127.0.0.1` in the project dir; run the headless Playwright QA per `references/browser-qa-playwright.md`. Attach console + pageerror listeners before `goto`. Assert every interactive surface with counts derived from the fixture data. For a single-file artifact that must work by double-click, also run a local `file://` smoke check when the interaction model depends on direct-file delivery.
6. **Vision pass, flags adjudicated in the DOM.** Screenshot primary viewports (desktop, data-heavy view, admin, 390px mobile) into the project folder; run each through vision_analyze — for a review pass, prompt each as a "harsh design audit: concrete problems only" so it returns prioritized specific violations instead of descriptions. Treat every vision flag as a hypothesis — measure (scrollWidth vs clientWidth, getBoundingClientRect, zoomed crop) before editing, and record disproven flags as false positives rather than "fixing" them.
7. **Fix and re-run the full suite** — not just the failed check. Every accepted vision flag becomes a permanent assertion in the check suite, so the suite ratchets and the finding cannot regress (bar widths equal their % labels, a chart legend total reconciles with the headline KPI, a micro-viz shows nonzero shape). On re-review, enumerate the accepted fixes as numbered "clean?" items in the vision prompt. Then deliver: MEDIA: paths for the screenshots, feature-to-implementation table, QA pass count and console-error status, and the skipped/when-to-add line. Deliver the final single-file artifact to BOTH the project root and `~/Downloads` with a README pointer at the root (what it is + how to open), and export per-screen element screenshots (Playwright element shots at deviceScaleFactor 2, named `<Board>-<Row>-<Role>.png`) plus the full-board PNG into `~/Downloads` alongside — attach only the new/changed screens inline; the set on disk is the record.

## Always-on rules

- Single self-contained file, zero remote JS/CSS dependencies — it must open by double-click as well as via http.server. Remote `<img>` URLs are allowed when the user explicitly asks for real product imagery, but always with `loading=lazy` plus an `onerror` fallback to a local category tile so the file still renders fully offline.
- Include the no-cache meta header; plain demo state is in-memory and resets on reload — say so in the UI and the delivery note rather than faking persistence. Exception: when the brief includes functional flows (admin CRUD, moderation queues, triage), implement real persistence per the localStorage-overlay pitfall below instead of "simulated" toasts.
- Demo credentials are never real: any email/password combination logs in, with the login modal stating it. Gate account/admin views behind the auth modal; role-gate admin with a visible toast on rejection.
- Accessibility floor: focus-visible styles, aria-labels on icon buttons, Escape closes modals, prefers-reduced-motion respected, responsive down to 390px with working hamburger nav.

## Real-data & site-reference upgrades

When the user asks to swap fictional demo data for real products (real name + real photo, invented specs/prices/reviews) or to "reference <site>" for design cues:

1. **Source product images by scraping official product pages, not search thumbnails.** Firecrawl v2 `scrape` with `formats:['markdown']`; take the page's og:image metadata plus the first `![](url)` images. Call the API directly (urllib/requests, `Authorization: Bearer <key>`) with `FIRECRAWL_API_KEY` from `~/.hermes/.env` — do this whenever the built-in web tools return 402/billing errors and the user has a key. For design-reference research the same curl + python tag-strip one-liner works: strip `<script>`/`<style>`, read visible text for structure and the repeated hex codes for the site's palette.
2. **GSMArena product pages are a reliable source of clean product shots**: the first image on a product page is `https://fdn2.gsmarena.com/vv/bigpic/<slug>.jpg`. Find pages via Firecrawl search `site:gsmarena.com <product>`. A wrong page ID loads a DIFFERENT product's page — the images scraped come from whatever actually loaded, so never trust a URL you didn't verify.
3. **Verify every image URL before embedding**: GET it with a browser User-Agent, require `Content-Type: image/*` and >5KB (small og:images are often site logos). Official CDNs (vendor image servers, Shopify, demandware) generally allow hotlinking.
4. **Vendor CDNs and GSMArena rate-limit (429) under batch verification — fall back to Wikimedia Commons.** Query the Commons API: `https://commons.wikimedia.org/w/api.php?action=query&format=json&generator=search&gsrsearch=filetype:bitmap <product name>&gsrlimit=8&gsrnamespace=6&prop=imageinfo&iiprop=url|size&iiurlwidth=960` (send a descriptive User-Agent); take `thumburl` from landscape results (width>height, width≥600) whose file title names the actual product. Commons thumbs hotlink reliably with no rate limiting — the better source whenever a catalog needs 10+ images verified in one pass; space same-CDN HEAD checks ~1s apart regardless.
4. **Wire in**: add an `img` field to the data array, render `<img loading=lazy ...>` with the onerror fallback (rule above), and keep the demo honest with a footer label like "Demo catalog: real products, illustrative specs and prices."

## Interactive 3D HTML scenes

When the brief requires a real 3D scene rather than a static illustration, keep the same single-file delivery and verification loop, with these additional steps:

For functional manipulable objects such as puzzles, product configurators, or layer-based 3D toys, also follow `references/interactive-3d-state.md`. It covers the scene/state split, pointer gesture arbitration, reversible transforms, and browser assertions needed to prove that visible manipulation updates the logical model.

1. **Choose the renderer before authoring.** Prefer an existing project dependency or a self-contained WebGL implementation. If a CDN module is the only practical route, state that the artifact is network-dependent and do not describe it as offline/self-contained; use a local vendored copy for true double-click delivery.
2. **Model interaction as acceptance criteria.** Implement orbit animation, pointer/touch drag rotation, wheel/pinch zoom, and a visible pause or speed control when animation is central to the brief. Add an explicit selected-object or reset affordance when the scene contains multiple bodies.
3. **Separate simulation from presentation.** Store orbital parameters and elapsed-time state in data objects, update each body's position from a shared animation clock, and keep camera controls independent from orbital motion. This makes speed changes, pause/resume, and deterministic QA possible without rewriting scene geometry.
4. **Verify behavior in a real browser, not by source inspection alone.** Attach `console` and `pageerror` listeners before navigation, assert that the renderer canvas exists, sample at least two frames to prove a planet changes position, dispatch a drag and verify camera rotation, and dispatch wheel or pinch-equivalent input and verify camera distance changes. Test both desktop and a narrow touch viewport when touch input is part of the brief.
5. **Verify the delivery contract separately.** Run the inline-module syntax gate, serve over HTTP, and inspect dependency URLs. A page can render a static shell while its module fails, and a successful HTTP response does not prove that animation or controls initialized.

Do not add decorative labels, legends, or control panels that are not connected to the live scene state: a polished 3D demo is still incomplete if its UI claims controls that do nothing.

## Design-option lookbooks

When the deliverable is several UI DIRECTIONS for the client to choose between (the current design plus alternatives in one page), follow `references/design-option-lookbooks.md`: faithful original mined from the real app's tokens, N distinct design languages over one content set, per-variant spec strips with trade-offs, merge-note footer. **Standing preference:** options share ONE color scheme whenever the user says so (or panel feedback is "defaultish") — variant variety comes from layout/structure/typography only, never palette; the reference's palette-lock branch and recolor pitfalls govern.

## Applying an enumerated feedback doc (coverage audit)

When the brief says "apply the suggestions" from a numbered list (panel feedback, meeting changes, review comments), the build is not done until every item is mechanically mapped to the artifact:

1. Extract the UI-visible items from the doc; classify each applied / partial / gap / skipped-by-design. An item the source itself gates ("confirm with client first") is a documented skip with a note — not a gap and not silent.
2. Grep the deliverable per item — case-insensitively, and split the file into per-instance segments (one screen/panel per segment) so each miss is attributed to the right instance. Case-sensitive greps over CSS-classed markup manufacture false gaps.
3. Deliver the coverage table with the artifact (item → where it appears → status). The user checks this work by asking whether the suggestions were taken — the table should already be the answer.
4. Some items target the PROTOTYPE's frame, not screen content (device/URL chrome, per-screen captions, layout arrangement). Map those to the frame layer, or they read "missing" forever no matter how good the screens get.

## Content bans and domain-model corrections

A mid-review correction that rules out content — a pricing pattern the user rejects ("no 20 percent off"), a UI affordance the product does not actually have ("it's any doctor", so there is no doctor picker) — is a constraint on the WHOLE deliverable: apply it to every instance and every frame, including a frame the build was told to leave untouched. The correction outranks the preserve rule; banned content goes, layout and structure stay. Enforce mechanically: strip tags and grep the visible text for the banned classes (promo/%-off/offer language, forbidden concepts) across all instances, then vision-verify the row. A concept-level ban removes the entire affordance — delete the picker card outright; do not reword it into a softened version of the same UI. A ban governs the banned FORM, not the whole category: if a later instruction re-enables the category (promotional content comes back at stakeholders' request), implement it in the compliant form — menu pricing, bundles, feature callouts — and keep the banned form out via the same mechanical grep.

## Pitfalls

- **Delegating a rebuild: one job = ONE `tasks[]` entry.** Each entry spawns an independent agent that cannot see the others — splitting one build into numbered "sections" dispatches duplicates racing on the same file. Stop extras via `delegate_task(action='stop', subagent_id=…)` and `steer` the survivor with the full brief.
- **Flash-class subagents die on the single big final write** — one model response emitting a ~80KB file exceeds their response budget, often after 40+ minutes of good research. Instruct them to author in appended chunks, or keep the final large write hands-on.
- **Delegation for READING works where delegation for WRITING dies**: a read-only copy/design auditor (deliverable = exact quoted strings + why + suggested replacement) pairs safely with hands-on patching — the write-death constraint is about concurrent authors on one file, not delegation itself.
- **Salvage dead subagents before redoing work.** Live transcripts persist at `~/.hermes/cache/delegation/live/<delegation_id>/task-N.log`; grep for verified artifacts (image URLs, research data, check results) — an agent that died at the final write usually leaves the whole research phase recoverable.
- **Restyling an existing prototype: remap token VALUES, keep token NAMES.** Swapping `--green`/`--orange` etc. to the new palette in `:root` restyles ~90% of the UI in one small diff (the var names are legacy, not semantic truth) — hunt only the hardcoded stragglers (topbar, hero, gradients) afterward.
- **Escape sequences through Python.** Never generate inline JS through a layer that processes escapes (writing the file from Python code): `\"` inside a JS string collapses to `"` and silently terminates the literal — the file renders but the script is dead. Write inch marks as `in.`, prefer single-quoted JS strings, and let `node --check` arbitrate. The same file-first rule covers multi-line Playwright/Node scripts: never push them through the terminal inline (`node -e`) — shell quoting mangles `$()`, nested quotes, and repr'd strings; write the script to a file and run `node <file>.js`, printing JSON metrics from it for the evidence record.
- **Truncation still reports success.** A verified write can be cut mid-tag on large files — the syntax gate plus tail-marker check is the detector; a broken close tag (`</\nnav>`) renders fine and hides the bug.
- **Formatted strings are not numbers.** In ranking/best-value logic pass raw numeric values plus a separate formatter — `Math.min` over rendered strings ("₱24,999") returns NaN and every highlight silently disappears.
- **Positivity clamps tuned to one caller's scale silently degenerate another caller's series** — a `Math.max(200, …)` floor that keeps chart values positive flattens any series whose base sits near 50 into a constant line, and existence checks ("the path is there") still pass. When one data generator serves two scales, assert shape (min amplitude or variance > 0) on every derived micro-viz.
- **A micro-viz must agree with the semantics of the number it illustrates** — a sparkline beside a negative delta, drawn in the down color but trending up, reads as a bug. Drive its trend direction from the delta, not from the data seed.
- **Budget card foot rows at the tightest column count** — delta chip + caption + sparkline that fit at 2 columns overflow at 4, and flex silently shrinks captions instead of erroring. Park the micro-viz absolutely in a card corner and reserve its width on the text rows (`padding-right`), then assert zero element overflow.
- **Sticky/fixed bottom bars need `main { padding-bottom }`** equal to their height — otherwise they cover the last rows of content at every scroll position, which vision QA will flag after the fact.
- **Functional flows need a store, not simulated toasts.** For admin CRUD/moderation/triage over demo data, write a localStorage-overlay module (one versioned key) applied over the base dataset on every load — stored copies of new/edited records, deleted-id arrays, per-id status maps. Rules that bite: load the store on EVERY page that renders the data, public pages included, or "approve → appears publicly" silently fails; rebuild derived lists INSIDE render() because the store mutates the dataset in place — a list captured at setup time is stale after the first action; default status is source-dependent (queue items pending, embedded records approved) so centralize the default instead of filtering mixed sources by status; deleting an item must also purge its per-id status/edit entries; validation guards (duplicate name, delete non-empty parent) go in the save path with the blocked button rendered `disabled`; recompute dashboard/metric numbers from the live dataset instead of hardcoded mocks.
- **QA-script traps:** opening a modal-bound input with `page.fill` fails on the hidden element — call the open function first. Assert counts recomputed from the fixture data, not assumed — a correct filter "fails" otherwise. After an in-page scroll use `behavior:'instant'` and wait before measuring geometry — smooth-scroll mid-animation gives stale rects and false overlaps.
- **Vision flags ≠ facts.** DOM measurement outranks the vision model: scrollWidth == clientWidth + complete corners in a zoomed crop ⇒ false positive, do not edit. Overlap claims need a post-scroll rect comparison, not a screenshot impression. The overflow check is only valid at the level measured: content cut by an INNER fixed-size frame (phone mockup, fixed-height card) clips while the page itself has no overflow — measure that container's scrollWidth vs clientWidth, and build frame rows to wrap (`flex-wrap`) with capped label type so they cannot clip.
- **When renumbering multi-step wizard steps, grep every hardcoded gate** (`recStep===N`, `Step X of N`, loop bounds `i<=N`) — a stale high-N gate silently skips its render callback and the step renders blank: the code exists but never fires.
- **Before deleting or renaming a function, grep the module for dispatch maps that name it** (`{page: fn}[attr]` routers, event registries). A dead key throws ReferenceError inside the shared `init()` on EVERY page that loads the module while each page's static shell still renders — it reads as a data bug on one page. Attach pageerror listeners before `goto` and treat a silent page as unproven: rendering proves nothing. The same silent-death class is call-before-init order: a render call placed above the state it reads throws at load and kills every later binding (listeners, charts, interactions) while the static shell paints — guard first-run calls (`if (chart) renderChart(...)`) and assert each feature actually initialized (chart has paths, list rows exist), not just that the page rendered.
- **Filter the count from the same array as the list.** Any "showing N of M" / tab badge computed from the unfiltered array while the list renders filtered contradicts itself on screen the moment moderation or deletion filters exist.
- **When deleting a step's inputs, grep each removed field name for dead readers** — leftover querySelector lines silently return defaults and template literals interpolate `undefined` into review/summary UI ("Routine undefined away from a charger").
- **Never offer a checkbox for a constraint the engine applies unconditionally** — a 'must stay below budget' chip on top of a hard budget filter is a no-op that erodes trust in every other option on the step.
- **Comparison-table ties are not wins**: best-cell highlighting must return 'no winner' when all values (or the only two compared) are equal, and the legend must state it — identical cells glowing as 'best' is a false statement rendered in the UI.
- **One concept, one name**: grep for synonym zoos ('monthly cost' / '₱/mo' / 'estimated ownership' / 'Cheapest monthly'; 'Index' / 'Ownership Index' / 'Intelligence Index') and standardize before shipping — the same figure under four labels reads as sloppy generation. Also fix invisible attributes (title/aria-label) that carry a stale full name.
- **Brand accent = interaction only; encode value semantics in green/amber/red** — score bars all in the accent color hide whether 38 differs from 100, and prices in accent read as links.
- **Transparent PNGs on tinted card backdrops render the product as black blobs** — put product images on a white backdrop, and verify each embedded image VISUALLY; HEAD 200 is not enough (a 200 PNG can still be unusable as a thumbnail).
- **Styled range sliders need explicit webkit track rules** — bare `accent-color` tracks fail 3:1 contrast; sync a `--fill` percentage custom property from JS for the filled gradient and give the thumb a white ring, or vision QA flags both.
- **Production QA on GitHub Pages must cache-bust (`?cb=<timestamp>`) for ~2–3 min after push** — the CDN serves the old build and false-fails bugs already fixed.
- **Write the prototype copy like a real product, not a school project** (user explicit: 'treat it like a website even though it's a prototype, no saying this is a placeholder'). Purge 'mock/placeholder/prototype' from user-facing strings and image alts; demo-state honesty lives in the footer/one line, not scattered labels. Editorial catalog copy (strengths, weaknesses, summaries) uses spec-based labels ('33W fast charging'), never voice ('rare in this class') — chatty asides read as AI-generated. A full-page screenshot with a 'Placeholder artwork' watermark undoes every polish pass.

- **Scripted edits to a generated artifact go through one atomic pass.** Split the file into per-instance segments, assert each pattern's exact match count before replacing, and write once after all asserts pass — a mid-script failure then leaves the file untouched instead of half-edited, and a duplicated anchor string surfaces as a count mismatch instead of a silent double-edit. To remove a whole block whose opening tag repeats across sections (the same card class on every phone), scan DOM depth from each candidate opening tag and delete only the block whose inner text matches a unique identifier — a string-count replace cannot select among identical tags.
- **Verify the mapping before zipping computed values onto repeated blocks.** When applying per-frame deltas (heights, offsets, colors) across N similar blocks, the regex match list must map 1:1 to the target elements in DOM order — a shared base value (e.g. one default height token in a global rule) or duplicated class string shifts the mapping and silently edits the wrong block; the frame that must stay untouched is often the victim. Prove the mapping by reconciling matches against measured element sizes (measured height = token − constant chrome). Generated mockup markup can also carry duplicate `style` attributes on one element — the parser keeps only the first, so read and rewrite the effective attribute or the edit no-ops.
- **Re-run the measure pass after every content- or height-affecting edit.** Thicker bars, added borders, inserted cards, and ANY typography change (font family, weight, size) re-overflow fixed-height frames even after the layout "fits" — text reflow moves every frame at once, so one font edit un-fits the whole board, not just the touched variant; a deleted card or shorter copy does the opposite — leaving an empty bottom gap at zero overflow. Refit against BOTH signals: grow each frame's height token by the measured per-frame overage (never shorten labels or trim content to fit), and shrink frames whose bottom gap (content bottom to frame/nav bottom) exceeds the row's target band — target a uniform gap across frames (~25-40px). `scripts/measure_frames.js <file> <frameSel> [contentSel]` prints per-frame gap and overflow in one run. Repeat until every frame reports zero over and uniform gaps before taking screenshots. The gap scales WITH the height token — apply `new height = current + (target gap − measured gap)`; reversing the sign over-corrects and costs a full regen cycle. When one frame reports both clipped content and a short gap in the same pass, `new height = current + max(clip, target gap − measured gap)` clears both in one step — and trust no gap figure while clip > 0 (clipped content shifts the measured bottom). The uniform gap target includes frame chrome: a bottom tab bar or fixed footer inside the frame raises it by that chrome's height (phone frames with a ~50px tab bar land near 72px, not the generic 25–40px band), so set the target from the tallest chrome in the row before refitting.
- **"Photo behind text" in existing markup: insert two absolute siblings (photo + scrim) right after the container's opening tag** and raise the real children with `> *:not(.hero-photo):not(.hero-scrim){position:relative;z-index:1}` — the container's closing tag is never touched, so the edit stays a two-line insertion instead of a parsing job.
- **Generated hero imagery is embedded once as a CSS class** (`background:url(data:image/jpeg;base64,…) center/cover`), compressed to ~640px JPEG first — one data URI shared by every element that uses it keeps the single-file artifact small and double-clickable.
- **Percent-height bars inside a flex row with `align-items: flex-end` render at zero** — empty wrapper divs size to their content under flex-end, so a 60% bar is 60% of 0px and the chart draws as an empty grid while the page "looks fine". Use `align-items: stretch` so wrappers span the track height, and verify rendered bar heights numerically after the fix. Data bars drawn in the pale track/tint color read as an empty skeleton state in vision review — draw the bars in the accent/primary and reserve tint for the track.
- **Uppercase tracked labels wrap at hyphens in narrow tiles** — the hyphen is the only break opportunity, so "FOLLOW-UPS" splits mid-word inside a ~70px stat tile. Give narrow tiles unbroken-word labels or `white-space: nowrap` plus measured width.
- **Mockup counters must reconcile across elements** — queue position = served + 1, chip totals equal stat-tile values, screens sharing data show equal counts. Contradictory numbers read as a data bug to reviewers even in a static mockup; where the board is generated, put the arithmetic in the selfcheck.
- **A render step that throws mid-command-chain does not stop the copy step after it** — `node shot…; cp out.png dist/` chains ship the PREVIOUS run's artifact as if fresh. After any failed screenshot/render, re-run it and check the shipped file's dimensions or mtime before delivering.
- **Generate boards of N near-identical frames from a builder script, not hand-copied markup** — one shared frame template plus a per-frame diff dict (height token, labels, variant bits) with a `selfcheck()` asserting structural counts and banned-wording regexes at generation time; keep refit heights in the builder so regenerating after an edit preserves the fit. Hand-copied frames drift out of sync on the first content patch. When extending the builder, grep it first for the established class name, helper, or image constant and REUSE it — an invented variant of an existing pattern (a new `.bar` where every frame uses `.prog`, an image constant that was never defined) renders zero-size or crashes at generation because its CSS/wrapper convention or definition lives under the name you did not use. Run the builder immediately after each structural edit: a SyntaxError at a `'''` or quote boundary means the inserted block landed outside the string literal — move the closing quotes past it.
- **Extending a frame builder to a new variant:** (a) extend scoped CSS blocks to the new variant's wrapper class by rewriting rule-start lines into a selector list (`sed 's/^\.pA \(.*\) {/.pA \1, .pB \1 {/'`, works when each rule's selector sits on one line) — duplicating the block invites drift; (b) give N-column tile grids a tile count that is a multiple of N (or explicit spans) — a dangling cell reads as missing data; (c) after any edit to a selfcheck assert or banned-word regex, re-grep the landed line for every intended pattern and flag — fuzzy patch matching can bind to a near-duplicate line and silently drop one, quietly weakening the gate.

skipped: backend/persistence/real APIs — prototypes are in-memory; wire to a real stack when the user moves to implementation.
