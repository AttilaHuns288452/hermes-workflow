## Architecture patterns (reuse, don't reinvent)

- `getEntity()` in `src/lib/entity.ts` — every server action entity-scopes through it (returns `{ supabase, entityId }` or `{ error }`).
- Merged actions: one server action returns page data + widgets (9→1 round trips was the July perf win). Keyset pagination on `(date, id)` DESC via PostgREST `.or()` with `limit(size+1)`; keep legacy 1-arg overload for stats callers.
  - **Promise.all batch pitfall:** destructured names bind POSITIONALLY to array elements — always APPEND a new query at the END of the batch (or reorder destructure names in lockstep). Inserting mid-array silently shifts both runtime data and tsc types for every later name (tsc catches it as confusing `Property 'x' does not exist on type '{...}'` errors — the real fix is the array order, not the types). One query can feed multiple derived fields (see `references/dashboard-widgets.md` — the dayTxns query now starts at `weekStart` and feeds ONLY `weekSpend` since the no-spend grid was deleted).
  - **date-fns v4:** `daysInMonth` does not exist — it's `getDaysInMonth`. `format(d, "EEE")` gives Mon..Sun labels; parse plain dates as `new Date(d + "T00:00:00")` so weekday math stays calendar-consistent.
- Validation layer: hand-rolled `src/lib/validation.ts` (validateAmount: finite, >0, ≤2 decimals with round-trip float check; validateDate strict yyyy-MM-dd + Date round-trip). `validateOptionalText` returns `""` for valid-empty, `null` ONLY for invalid — callers check `=== null` for errors.
- Server-derived state: status/submitted_by computed server-side from role — never trust client-passed workflow fields.
- Money math: `round2 = Math.round(x*100)/100` on every line_total/subtotal/total; validate non-negative discount/tax/price; **reject the whole record with "Line N: …" on bad lines, never silently filter them**; DB CHECK constraints (`total >= 0`) as backstop; retry once on unique violation 23505 for generated numbers.
- Invoice/PO status = explicit transition map (draft→sent→paid, void from draft/sent) — never free transitions.
- **Core schema map (verify in `supabase/migrations/` before deriving data — briefs often assume wrong shapes):** `investments` (ticker, name, asset_type `stock|etf|crypto|mutual_fund|reit`, quantity, avg_price, purchase_date, notes, **yield_pct DECIMAL(5,2)** — migration 015, drives Passive Income) is the portfolio source of truth; `assets` is ONLY liquid/illiquid net-worth rows (no per-asset tickers/yields). `transactions` (type income|expense, amount, category_id → `categories(name)`, description, date, status pending|approved|rejected — expense stats filter `.neq("status", "rejected")`). `debts` is ONLY `id, entity_id, name, amount, updated_at` — **no apr/min_payment/interest columns**; payoff projections use defaults (see `references/debt-payoff-module.md`).
- Reuse, don't rebuild: `getPortfolioWithPrices()` from `src/features/investments/actions.ts` enriches holdings with market values (CoinGecko via `market-data.ts`); cross-feature imports are normal. Client currency: `getCurrencySetting()` from `@/features/settings/actions` + `formatCurrency()` from `@/lib/currency`.
- PostgREST `.or()` supports embedded columns: `.select('id, date, description, amount, categories(name)').or('description.ilike.%dividend%,categories.name.ilike.%dividend%')` — join is RLS-safe (dashboard already uses the same embed).
- Sidebar: `navSections` in `src/components/layout/AppShell.tsx` (segment personal|business). New links: reuse an already-imported lucide icon, ADD a line only — never restyle existing lines (repo mixes quote styles; new files per sprint brief: 2-space, no semicolons, single quotes).

## RLS / Supabase pitfalls (learned the hard way)

- **Views bypass RLS by default** (security definer): any `CREATE VIEW` over RLS tables must be `CREATE OR REPLACE VIEW … WITH (security_invoker = true) AS …` or any logged-in user reads every entity's data. This was a HIGH cross-tenant leak.
- Staff-scoped RLS: `public.current_staff_role(entity_id)` SECURITY DEFINER function (owner via `entities.user_id`, else staff row match) + owner-full/staff-read policy pairs on every table, including child tables (invoice_lines/po_lines via parent join).
- PostgREST probe verification: `curl "$URL/rest/v1/<table>?select=id&limit=1"` with anon key → 200 means table + RLS live. Probe every new table + view after the user runs a migration.
- Indexes can't be introspected via PostgREST — to verify a unique-index migration (e.g. 020 import-key backstop on `transactions(entity_id, date, amount, coalesce(description,''))`) is live, attempt a duplicate insert and expect a 23505 violation. Easiest token: password-grant (`POST /auth/v1/token?grant_type=password` with anon key + test creds) — no JWT minting needed. HTTP 201 = constraint NOT applied (proven for 020 in 2026-08-06); clean up any landed row via `select=id,created_at&order=created_at.desc`, delete the newest. git-bash pitfall: Windows curl `-o /tmp/x.json` writes to `C:\tmp` (MSYS vs Windows path mismatch) so the later git-bash read of `/tmp/x.json` fails — write probe bodies to a repo-relative path.
- **Table-sweep probe (caught migration 009, 2026-08-06):** after ANY migration round, sweep ALL tables the app queries, not just new ones — `grep -oh "\.from([\"'][a-z_]*" src/ --include="*.ts" | sort -u` then loop `curl -o /dev/null -w "%{http_code}" "$URL/rest/v1/<t>?select=id&limit=1"` with a user token; 404 = migration never applied (loans was missing → Loans page broken in prod while the code shipped). The user's paste flow skips migrations silently and "user said done" is not evidence — probe. Full recipes: `references/migration-verification.md`.
- **Verify agent-written migrations against the originals before shipping to the user** (2026-08-06: migration 021 review caught 2 issues): a fix migration that DROPs+CREATEs policies must reproduce the ORIGINAL USING clauses exactly (a changed gate is a silent permission change); `CREATE OR REPLACE FUNCTION` must keep the exact original signature/body (callers break on arg drift); any UNIQUE index over existing data needs a dedupe DELETE first. **Dedupe safety (ECC-resolved design):** delete ONLY `status='pending'` rows (`AND a.status = 'pending'`), keep the chronologically first per key via `(a.created_at, a.id) > (b.created_at, b.id)` (v4 UUIDs are random — `a.id > b.id` is a coin flip that can delete the PAID run and cascade its lines via ON DELETE CASCADE); a surviving paid row blocks nothing; two PAID runs for one period (pre-existing double-pay) make the index fail LOUDLY — deliberate, never silently drop paid history.
- **SECURITY DEFINER guards MUST test `auth.uid() IS NULL` explicitly** (2026-08-06: my own 021 `notify_user` guard shipped this bypass, caught by 2 ECC reviewers): `IF p_user_id <> auth.uid() AND NOT EXISTS(…)` is NULL for anon callers (`p_user_id <> NULL` = NULL → IF skips → the definer insert proceeds). Pattern: `IF auth.uid() IS NULL OR (…) THEN RAISE EXCEPTION`. Also: don't forget the `SET search_path = public` + exact original signature on CREATE OR REPLACE.
- **Policy changes must be diffed against app-layer status derivation** (021 `txn insert for staff` initially allowed approved only for `owner`, but `createTransaction` sets `status: canApprove(role) ? 'approved' : 'pending'` → every manager write broke with a raw RLS error): the WITH CHECK carve-out must be `current_staff_role(entity_id) IN ('owner','manager')` — the app's canApprove set — not just owner. When a migration tightens RLS, trace every server action that writes that table's gated columns first.
- `submitted_by`/approvals: app-layer role checks are NOT enough — RLS was owner-only, which made the whole approval workflow inert for staff until migration 011 added staff policies.
- **signUp seeding vs email confirmation (HIGH, 2026-08-06):** `src/features/auth/actions.ts` creates the personal entity + 12 default categories in the signUp server action, and migration 001 removed the DB trigger ("Former DB trigger removed for reliability"). With email confirmation enabled (the UI's "Check your email" screen implies it), signUp returns no session → inserts run unauthenticated → RLS blocks → confirmed users log in with NO entity and no retry path. **FIX SHIPPED:** idempotent `ensureEntityAndDefaults(userId)` in auth/actions.ts (checks entity exists, creates personal entity + 12 defaults reusing the signUp seed list) + glue in `getDashboardData` — when `getEntity()` fails, fetch the user via `createClient().auth.getUser()`, run ensure, retry `getEntity()` once. Heals existing broken accounts on first dashboard load; keep the signUp-time call for the no-confirmation path.

Compact plain-text lines: entity, month income/expense/net, net worth (assets − debts), top-5 spending, budget spent/limit (match by category NAME from month txns), goals, recent txns, debt count. Amounts via `formatCurrency()` from `@/lib/currency` (reuse, don't re-format).
- **Explainable Cashy (2026-08-11 P1, shipped in `AIAssistant.tsx`):** live month stats were ALREADY in `getCashyContext()` — no server change needed (read the existing action before building the brief's assumed gap). - **Never ship fabricated seed data** (fake "$4,820" insights, fake badges) in a finance app — reviewers flagged it as a MAJOR. Cashy only relays API output.

## Sprint pipeline (proven, repeat)

1. Scope from schema first: read migrations + feature dirs before writing briefs.
2. Dispatch 2–3 parallel subagents (deepseek-v4-flash) with **disjoint file ownership**, each: `tsc --noEmit` only (NEVER `npm run build` — `.next` contention), local commit, no push.
   - **Cap a delegate at ~5–6 files / one component cluster** (2026-08-11: a 10-finding/6-file single brief timed out at 600s with 3 items unlanded — the parent finished them; splitting into 4 single-cluster streams finished clean). When one agent must own one big file (e.g. TransactionList.tsx), give it a numbered per-item spec list and expect to finish stragglers as parent.
   - **Kanban tracking: use the Hermes built-in `hermes kanban`** — the `ak` CLI errors `Could not locate hermes process in ancestry` when run from a plain terminal; `hermes kanban boards create|switch <slug>` then `hermes kanban create "title"` (no `--board` flag on create — tasks land on the ACTIVE board, switch first).
   - write_file/patch inline lint can false-positive `TS6053: File not found` on this Windows/MSYS host immediately after a successful write — trust the final `npx tsc --noEmit`, not the inline lint. **`&&`-chain trap when self-checking before tsc:** `node -e '...' && npx tsc --noEmit; echo "TSC_EXIT=$?"` — if the node check fails, `&&` skips tsc and `$?` prints the NODE exit code, masquerading as a tsc failure (misread once, 2026-08-11); run verification steps as separate calls or echo each step's code.
   - Parallel-repo discipline: `git add <your exact paths>` — NEVER `git add -A` (you'll commit a sibling agent's in-flight files; verify with `git status --short` that only your files are staged). Sibling agents/parent may `git add` YOUR files mid-sweep (staged `M ` with no unstaged diff) and rewrite them CRLF — harmless, never unstage/commit; verify on-disk state with terminal `git hash-object <file>` vs `git rev-parse :<file>` + `grep -c` your markers before trusting read_file (torn/stale reads observed mid-sweep), re-read before each patch.
   - Pre-existing tsc errors in ANOTHER agent's files: verify your own files compile clean, report the rest as out of scope, don't fix them. Quote style when patching an existing file: match THAT file's style (repo mixes double-quote+semicolon and single-quote+nosemicolon files); new files follow the brief's style.
   - Parent-side tsc baseline: `npx tsc --noEmit 2>&1 | grep -v '^\.next/'` — an interrupted `next dev` leaves `.next/dev/types/routes.d.ts` stale-corrupt (TS1434/TS1128/TS1109) while src stays clean; filter generated files before reading the result (Sprint 2 baseline was clean once filtered).
   - Regression/polish sweeps: run an AUDIT-ONLY wave first — read-only agents with disjoint feature clusters, embedded design-language + bug-class checklists, report contract = severity table (File:line | Issue | One-line fix), explicitly forbidden from editing/building/gitting — then a fix wave from the findings. Browser E2E sweep goes to ONE separate agent — give it EXACT agent-browser commands in context and require `timeout 45` wrappers around every call; do NOT tell it to load/read the agent-browser skill docs (name collision with the vercel copy burned 9 min; a hang then ate the rest). Screenshots written before a timeout ARE the deliverable — run MiMo visual QA on them instead of re-running the sweep.
   - Fix-wave briefs that maximize partial landings under the 600s cap: per-finding "file:line + one-line fix" lists, strict file ownership, "match the file's quote style", "tsc --noEmit only, fix ONLY errors in YOUR files", "never git add/commit". Expect agents to land server actions + small components, then die before the component-heavy files — finish those as parent or a second focused wave; check `git diff --stat` before re-dispatching anything.
   - **TS `in`-narrowing quirk** (bit twice in one recovery): `if ("error" in data) return data;` FAILS to narrow when the function's return type is INFERRED — TS synthesizes `error?: undefined` on the sibling member, the `in` check matches both, and the whole union flows where a narrowed member is expected (TS2322/TS2339 on every property access). Fix: annotate the function with an EXPLICIT union return type (`Promise<{ error: string } | { ...success }>`) — narrowing then works. Bites every time an agent changes a server action's return shape and the parent bridges the callers. Callers of OVERLOADED paginated actions need `type T = Extract<Awaited<ReturnType<typeof fn>>, { items: any[] }>` — `ReturnType` picks the LAST overload, so a bare `Awaited<ReturnType<...>>["items"][number]` fails on the union (TransactionList.tsx pattern).
3. Parent: merge verify (tsc + `npm run build` + impeccable detector) → ECC review — baseline `code-reviewer` + `silent-failure-hunter` in parallel, UI batches add `a11y-architect` (3 agents); scope each goal to the UNCOMMITTED `git diff` (changed-file list + concrete invariants, read-only, no edits) → fix findings → push → live curl check.

## Recurring review-finding classes (pre-ship checklist)
