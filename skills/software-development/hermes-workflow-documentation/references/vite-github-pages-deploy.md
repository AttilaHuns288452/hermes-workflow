# Vite → GitHub Pages Deployment Pitfalls

## The White Screen Problem

A Vite React app deployed to GitHub Pages shows a blank white page because the **source** `index.html` is served instead of the **built** one.

### Root Cause

The source `index.html` references Vite dev paths:
```html
<script type="module" src="/src/main.jsx"></script>
```

Browsers can't resolve this because:
- `import from 'react'` — bare module specifiers need a bundler
- `import './index.css'` — native ES modules can't import CSS
- `import './App.jsx'` — JSX needs transpilation before the browser sees it

### Fix

```bash
# Build the app
npm run build

# Copy built files from docs/ (or dist/) to repo root
cp docs/index.html .
cp -r docs/assets ./
cp docs/favicon.svg docs/icons.svg .  # public files
cp docs/.nojekyll .                   # prevent Jekyll processing

# Commit and push
git add index.html assets/ favicon.svg icons.svg
git commit -m "fix: deploy built Vite output to root for GitHub Pages"
git push
```

### Detection

| Check | Command | Healthy |
|-------|---------|---------|
| HTML is source or built? | `curl -sL <url> \| grep "src="` | Should show `/repo-name/assets/index-xxx.js`, not `/src/main.jsx` |
| JS MIME type | `curl -sI <url>/assets/index-xxx.js \| grep Content-Type` | `application/javascript` |
| CSS MIME type | `curl -sI <url>/assets/index-xxx.css \| grep Content-Type` | `text/css` |
| CSS/JS loadable | `curl -so /dev/null -w '%{http_code}' <url>/assets/index-xxx.js` | `200` |

### Prevention

The `vite.config.js` controls this:
```js
base: '/repo-name/',            // must match GitHub Pages path
build: { outDir: 'docs' }       // GitHub Pages can serve from /docs or we copy to root
```

**Configure GitHub Pages to serve from `/docs`** (if you have repo admin) in Settings → Pages → Source → `/docs`. This is the cleanest setup — no file copying needed, and `vite build` always works because root `index.html` stays as the Vite entry point.

Or add a deploy script (note: copies assets but NOT index.html to root — see warning below):
```json
{
  "scripts": {
    "deploy": "npm run build && git add docs/ && git commit -m 'deploy' && git push"
  }
}
```

### ⚠️ CRITICAL WARNING: Never overwrite root `index.html` with built output

The fix above suggests `cp docs/index.html .` — **do NOT do this as a permanent setup**. Copying the built `index.html` (with hardcoded hashed asset references like `index-Co6ofMD_.js`) to the repo root **breaks `vite build`** on the next run:

```
Error: Failed to resolve /hermes-workflow/assets/index-Co6ofMD_.js from index.html
```

**Why it breaks:** Vite's entry point is root `index.html`. It must reference `/src/main.jsx` (the source entry). When you overwrite it with the built version, Vite tries to resolve stale hashed asset filenames that either don't exist or have different hashes after the next build.

**The correct setup:**
1. Root `index.html` → always references `/src/main.jsx` (Vite dev entry)
2. `docs/index.html` → generated by `vite build` (built entry for GitHub Pages)
3. GitHub Pages serves from `/docs` branch setting — root `index.html` is never served to users

**If you already broke it** (root `index.html` has hardcoded hashed assets):
```html
<!-- BROKEN — root index.html has this: -->
<script type="module" crossorigin src="/hermes-workflow/assets/index-Co6ofMD_.js"></script>

<!-- FIX — restore to Vite entry: -->
<script type="module" src="/src/main.jsx"></script>
```

After fixing, run `npm run build` to regenerate `docs/` with fresh hashes, then verify:
```bash
npm run build                                    # must pass
npx vite preview --port 4173 &                   # serve docs/
curl -s -o /dev/null -w '%{http_code}' http://localhost:4173/hermes-workflow/  # expect 200
curl -s -o /dev/null -w '%{http_code}' http://localhost:4173/hermes-workflow/assets/  # expect 200 on JS+CSS
```

### Browser Cache

After pushing the fix, the CDN takes 1-3 minutes. If the page still shows white after that:
```
Ctrl+Shift+R  (hard refresh)
```
Or clear site data for `username.github.io` in browser settings.
