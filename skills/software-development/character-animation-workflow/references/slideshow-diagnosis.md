# Slideshow Diagnosis — Root Cause Checklist

When a user says "my video is a slideshow" or "why is this just text over images," run this checklist before touching any code.

## Step 1: Pipeline Audit (90% of cases)

Check which pipeline the current project is using:

```bash
ls pipeline_defs/ | grep -E "$(cat PROJECT_CONTEXT.md 2>/dev/null | grep 'Pipeline:' | head -1)"
```

Or look at the project's artifacts for `edit_decisions.json` / `composition.json` / `scene_plan.json`.

| Pipeline | Output Style | Character Animation? |
|----------|-------------|---------------------|
| `animated-explainer` | Text cards + images + spring fades | ❌ Slideshow |
| `character-animation` | SVG-rigged characters, pose libraries, action timelines | ✅ Real motion |
| `animation` (image_animation) | Multi-image crossfade, camera motion, particles | ✅ Feels animated |
| `clip-factory` | Stock footage + text overlays | ❌ Slideshow |
| `cinematic` | Video clips + transitions | ✅ Real video |

**If the pipeline is `animated-explainer` and the user wants character animation — STOP.** Do not try to fix the render. Switch to `character-animation`.

### Exact Signal: "why is my videos just a good slideshow not animated story or something"

This exact phrasing is a CLASS-1 complaint that the wrong pipeline is in use. The user is telling you the output lacks character acting and motion — they are NOT asking for better text cards, better transitions, or better overlays on the Explainer pipeline.

**Correct response**: Audit the pipeline immediately. If it is `animated-explainer` or any FFmpeg-slideshow-based pipeline, switch to `character-animation`. Do not spend even one more cycle on the Explainer pipeline.

**Wrong response**: Try to improve the Explainer output with more scenes, better assets, GTA overlays, or spring animations on text cards. This was the actual mistake made — multiple sessions were wasted polishing the wrong pipeline before making the obvious switch.

## Step 2: Asset Loading Failure (Windows-specific)

On Windows, `file:///` URIs generated by `resolveAsset()` in `Explainer.tsx` are blocked by headless Chrome. This causes all images, audio, and music to fail silently. The video renders with backgrounds only — text on a colored canvas.

**Fix**: Move assets to `remotion-composer/public/assets/` and reference them as `/assets/...` (Remotion serves them via HTTP, bypassing the file:// restriction).

**Symptoms**: Render completes without errors but all assets are missing. ffprobe shows correct duration but video is visually blank/colored-background-only.

## Step 3: Asset Path Format

Remotion expects paths in `public/`-relative format:
- ✅ `/assets/images/hero_bg.png`
- ❌ `file:///C:/Users/...`
- ❌ `C:\Users\...`
- ❌ `./assets/...`

Check the props JSON passed via `--props=` for any absolute Windows paths.

## Quick Triage

```
User: "It's a slideshow"
  → Check pipeline name in project artifacts
    → animated-explainer? SWITCH TO character-animation (do NOT fix Explainer)
    → character-animation? Check asset paths for file:// URIs
    → other? Check composition.json / edit_decisions for scene variety
```
