# Web App Release QA

Full-product audits, adversarial/multi-role QA, design-fidelity verification, and iterative test-find-fix-regress loops until the app is release-grade. Trigger words: audit, stress test, break it, production-ready, shippable, fidelity, "fix all" / "apply the fixes" after a report.

## Always-on rules

1. **Audit means document, not fix.** In an audit phase, record current state first; never silently patch while auditing. Fixing starts only when the user says to apply the fixes.
2. **Never fabricate test results.** Everything reported as PASS was actually executed. Unverified items are `NOT TESTABLE` (with reason) or `BLOCKED`. An inconclusive probe is not a PASS and not a FAIL.
3. **Frontend behavior is not evidence.** A button works only when the database changed and persists across refresh and re-login. Authorization is only what the server enforces. Optimistic UI state (a handler that updates local state after a silent or failed write) fakes this — the verdict is the database read-back; a green UI check over a failed write means the handler swallowed an error.
4. **Every fix passes regression before being called fixed:** original repro → surrounding workflow → related cross-role flows → DB state → UI state → refresh → re-login.
5. **Preserve the stable version first** (git tag / commit) before a fix pass.
6. **Test-infrastructure hygiene:** delete only rows belonging to the suite's own test identities (patients/users the suite itself creates) — identity scope first, date-bounding second; never date-only or pattern-only deletion, it eats seed data. Self-clean at BOTH start and end: crashed runs leave residue that collides with the exact guards under test. Clean by the run's identity marker and count EVERY matching row — leaked rows from earlier crashed runs skew exactly the uniqueness/duplicate guards under test. Keep a canonical seed row map (shared by seed + cleanup scripts); when a cleanup eats seed rows anyway, restore via the seed script and disclose it — do not chase the row count by deleting more. If a probe mutates real rows, restore them to their exact prior values and disclose it in the report.
7. **Dev/QA tooling hides behind a flag** (`?dev=1` + localStorage), including one-tap role logins and mock payments. Mocks must travel the REAL backend path (real RPC/endpoint) so downstream analytics reflect them. Default state must contain no dev UI.
8. **A failing check is a hypothesis.** Triage every FAIL to harness-defect vs product-defect with a minimal probe (DOM dump, API read-back, single-flow replay) BEFORE editing product code; when a product fix results, that probe becomes its runnable check. Suite asserts track presentation copy: only a USER-DIRECTED design change may update a failing assert (and then log the deviation) — never revert a directed design to satisfy a stale assert. Conversely, a committed gate that was green and flips red after your own unrequested behavior change is the spec: restore the behavior or ask the user; do not weaken the assert to bless your change.
9. **A confirmed root cause ends diagnosis.** When the cause is established and the user asked for a fix, the next call is the patch plus its runnable check — re-probing the same state is the failure mode ("not doing the actual job"), not diligence. Reserve extended probing for unconfirmed causes or an audit phase the user explicitly asked for. After the user judges a fix broken, switch to audit-first: diagnosis only plus a current → problem → correct correction map for approval, then one tightly-scoped fix ("only these two sections, touch nothing else").
10. **A control that claims to change a parameter must demonstrably change the state it governs.** After wiring a selector/slider/toggle, verify the BEFORE/AFTER of the actual representation (trace, drawn label, computed result) — a control that exists, is visible, and reports no errors can still change nothing (missing change handler, unhooked state). Presence of the control is not evidence.
11. **Teammate work is a scope gate.** When the repo carries a teammate's recent PRs: verify integration first (`gh pr list` — every PR of theirs merged, local == origin) before claiming it is integrated, and present the fix plan with reasoning for the user's approval BEFORE editing their files — plan-then-approve is the standing preference for other people's code. When an audit flags behavior that is the product's INTENDED model (e.g. shared clinic-wide visibility in a single-clinic app), get the owner's decision, record it in the scope document, and fix only the enforcement side — never build the flagged architecture or silently "fix" intended behavior.

## The loop

> Inspect → Compare → Implement → Test → Find failures → Fix → Retest → Regress → Repeat

Do not stop after the first passing cycle or because the happy path works. Continue until the acceptance gate (below) is met.

### 1. Inventory + requirements matrix

Enumerate roles, shared vs role-specific pages, protected routes, and every button/form/list. Track as `requirement | reference | expected behavior | implementation | backend support | PASS/PARTIAL/FAIL/MISSING/BLOCKED/NOT TESTABLE`. Keep it current as fixes land.

### 2. Compare against the reference set (reconcile, do not blind-copy)

Source priority when references disagree: **latest product video = behavior/flows; latest Figma = visuals/layout; accumulated user feedback = regression tests.** For responsive/visual passes (route × viewport × role screenshot matrices with programmatic overflow/target/nav-chrome checks plus batched vision review), see `references/visual-qa-matrix.md`. For the fast vision-free responsive gate (every route × extreme widths × engines: overflow + clipped-text + page-error scan), run `scripts/responsive-sweep.cjs` (method in the same reference). Never reintroduce a flow the user previously rejected just because an older frame contains it (removed tabs, approval queues). Figma sets carry exploratory, outdated, and duplicated states — and the visible navbar is part of a frame's identity (the same page exists in per-role variants). When pixel comparison is impossible, compare `pdftotext -layout` structure against the app DOM and hand the user both screenshots.

### 3. Per-role live walkthroughs

One session per role, natural user sequence (login → core journey → edit → logout → re-login), verifying at each step: correct screen, validation, DB mutation, resulting state, persistence after refresh. Then stress each role: empty submits, double-clicks, stale pages, back button, wrong routes, manipulated IDs, cross-user access attempts.

Role-scoped information requirements ("a doctor must never see clinic
revenue", "financials are owner-only") get their own audit in both
directions:

- Grep the frontend for the information's markers (currency symbols,
  income/revenue/billing keywords) and enumerate every surface that can render
  them: pages, shared card/tile components, nav/tab configs, and shared
  branches that serve more than one role.
- Prove each role's view from RENDERED text: inject that role's session before
  `goto`, dump the region's `innerText`, and assert presence for the owning
  role AND absence for the others. Match case-insensitively — CSS
  `text-transform` makes a case-pinned absence check pass vacuously.
- Fix by whitelist, not by omission: gate the shared branch on the privileged
  role (`role === 'owner'`), so future roles inherit the hidden default.
  Removing the card from one role's branch leaves the next shared branch
  leaking the same data.
- Keep the owning role's access intact in the same change; a leak fix that
  also breaks the owner's dashboard fails the same brief.

### 4. Cross-role live simulation (the centerpiece)

Run all roles together as one business scenario with separate sessions: actor acts → every role sees the effect → DB readback as that role (their own client, not the service key) → a second role mutates → all see it → refresh everything → re-login everything → states hold. No contradictory states across roles.

### 5. Action safety (confirmation dialogs and consequential actions)

Classify every mutating action before polishing its feedback:

- **Destructive, irreversible, or hard-to-reverse** (deletes, clearing history
  or saved collections, account closure, admin destructive ops, sign-out) get
  an in-app confirmation dialog. **Ordinary reversible toggles** (wishlist,
  compare selection, filters) act immediately with a toast - a confirm step on
  reversible clicks is friction, and the user rejects it.
- Row-level trash/icon buttons are where immediate unconfirmed deletes hide;
  audit those first, including admin tables where deletion looks routine.
- One shared confirm-dialog primitive on the app's existing modal (focus trap
  and Escape come from the base): title + a consequence-stating message that
  NAMES the item, context-specific action labels ("Delete", "Sign Out" - never
  a bare "OK"), neutral vs danger emphasis, a busy state that disables BOTH
  actions AND swallows Escape/backdrop close (a running operation can be
  neither double-submitted nor abandoned half-way with a lying UI), and an
  inline error slot for the failed case. Never `alert()`/`confirm()`.
- Navigation and state cleanup happen only after the awaited result: sign-out
  that navigates at click time reads as success when the logout fails.
- The dialog is UX, not a security boundary - the same action stays enforced
  at the data layer (see `webapp-release-qa` -> `references/backend-trust-boundaries.md`).

### 6. Adversarial + integrity passes

Attack at the API with throwaway accounts; sweep for orphans/dupes/invalid status combos; recompute displayed totals from source rows and compare. `references/adversarial-testing.md` has the attack checklist and bug report format.

### 7. Fix + regress

On "fix all": apply root-cause fixes P0→P2 (one shared guard beats per-caller patches), then re-run the ENTIRE battery. A fix that breaks a sibling flow is not done. Backend trust-boundary fixes: `references/backend-trust-boundaries.md`. Bottom-chrome overlap (tab bar covering a composer, FAB over a button, keyboard over the input): causes → fixes → reproduce/verify recipe in `references/bottom-chrome-overlap.md`, runnable harness in `templates/composer-qa.cjs`. CSS-cascade and interaction-stranding render failures (border accents killed by divide layers, reduced-motion freezing animations, stranded carousel drags, stale-tab symptoms): mechanics + fix code in `references/tailwind-render-pitfalls.md`.

### Fix-quality pitfalls (fixes that make it worse)

- **Never fix perceived density or size by scaling a UI shell** (`zoom`, `transform: scale` on the app root, panel, or console). It scales every descendant — hit targets, fixed chrome, borders, hit geometry — and the user reads the result as "this screen is zoomed in". Change the type scale / spacing tokens at the component level instead. Diagnose a FELT zoom ("this screen looks bigger than the other one") by measuring `getComputedStyle(…).fontSize` on equivalent real elements in BOTH surfaces: a matching root `font-size` and `zoom: 1` proves nothing, because one surface can inflate its type twice (a token step sitting a scale step high, then multiplied by a desktop `--ui-scale`) while the other sizes in raw px and never scales. Converge on one sizing system; deleting a scale multiplier without lowering the token step leaves the type oversized.
- **A two-column detail layout with unequal column heights blanks the short column on scroll.** Sticky the short column (product media / sidebar) against the long one before restructuring content; measure both columns' heights first to confirm the imbalance is the cause.
- **Mount toasts/feedback hosts at the document root, and only while non-empty.** A host inside the page root inherits the root's route-transition stacking context and is painted under modal scrims (its dismiss button looks clickable and is not); a host inside a hovered card inherits that card's `transform` and is positioned against the card, covering the card's own controls; and an always-rendered host gives every repeated row its own `aria-live` region (a 240-card list then announces through 240 live regions). `createPortal` to `body` plus render-when-non-empty fixes all three.
- **A per-row hook that fetches on mount multiplies into a request storm.** N repeated cards each running an auth check and a per-user fetch issue N×3 backend calls on one page load. Share the in-flight promise per user at module level, or hoist the fetch to the list and pass it down — and count the requests in the harness before calling a list page healthy.
- **Never overwrite persisted local state with an empty backend read.** A sync path that replaces the local store wholesale wipes user data on the first read that happens to come back empty (before a mirror row exists, or after any transient empty response). Merge the sources and treat an empty read as "nothing to merge", never as "delete".
- **Guard every submit against concurrency, and never emit a success message before the write branch resolves.** One double-click creates two rows without a busy flag plus a disabled button; a slow load that settles after a newer toggle clobbers the newer state into a destructive sync (sequence the writes and drop results the user has superseded); and a success toast fired at the click handler tells a gated guest "saved" while the sign-in prompt opens. Verify each with a double-click repro, a rapid-toggle repro, and a count read-back.
- **A reserved N-line text box must be re-derived whenever the type scale changes.** A `min-h` sized for the OLD line-height becomes taller than N lines after a token change, so N.5 lines paint inside it and collide with the row beneath while still looking "clamped". Pin the block to exactly N lines (`h-[<N lines>] overflow-hidden` alongside `line-clamp-N`) so the reservation and the clamp agree, and recompute that height in the same commit as any line-height or font-size change. Never add a `display` utility to a `line-clamp` element — `block` overrides the clamp's `-webkit-box` and silently disables it.
- **A CSS entrance animation never replays on state change.** React reuses DOM nodes, so filtering or sorting a list leaves every element's animation already finished - the list updates with zero motion and the feature reads as missing. Drive the animation from a value that changes with the state (put the sort/filter value in the `key`, or bump a counter on the wrapper) so nodes remount, and prove the replay with a computed-style sample shortly after the change rather than by watching. The mirror case: an entrance animation on a persistent parent (`<main>` with no `key`) runs once on first paint and never on route navigation, so a route "transition" authored as a CSS animation is dead code until the parent is keyed. And when proving motion is VISIBLE at all, use frame-level pixel diffs of the rendered page - `animationstart` events prove the code executed, not that anything moved on screen; the page-appear paint dominates any single-frame diff, so stage choreography after first paint to make the sequence measurable.
- **Unbreakable text from users or echoed input must wrap.** A long token (a search query, an unspaced product title) laid out with `whitespace-nowrap` or a fixed width widens the whole document at every viewport, or is sliced mid-word by a card's `overflow: hidden`. Apply `overflow-wrap: anywhere` wherever user-derived text renders, and assert `scrollWidth <= innerWidth` with data present.

## Live-deployment verification (production URL)

When the target is the deployed site, the local loop is not evidence. Add these steps around the same battery:

1. **Pin the revision before testing.** Read the deployment record's commit sha (deployments API, `meta.githubCommitSha` for the READY production deployment) and match it to `origin/master`, plus one behavior marker in the served bundle. "Deploy succeeded" is not "the revision under test is live": a throttled or stalled deploy serves the previous build.
2. **Cache-bust params must not corrupt the probe URL.** `?cb=N` when the URL has no query, `&cb=N` when it has one. A `?cb` appended after `&params` rewrites the last parameter value and the server answers 400 for input that is actually valid — when an API probe reports a surprising validation failure, re-send with a clean URL before calling it a product defect.
3. **Fixed sleeps race async readiness gates.** Session restore and role checks (e.g. an `is_admin()` RPC) resolve after first paint; a hard sleep can land inside the gate's window and read as "button missing" or "redirect bug". Wait for a signal that exists only after the gate passes, and test route guards with `page.reload()` / a cold tab — in-app navigation keeps the resolved state and hides the race. The product-side root cause is a guard that marks its async check DONE on its first pass while the session is still restoring (guard sees `!user`, concludes "checked, not admin", redirects a real admin). Fix at the guard: treat auth as a three-state (loading / resolved) and only decide when the session has settled; the symptom (fast deep-link bounces to home, in-app navigation works) is the tell.
4. **Assert layout and counts AFTER data loads.** Loading/empty states contain no cards, charts, or long labels: overflow and text-clipping defects appear only once real rows render. Sample at a fixed early sleep only to verify the loading state; verify geometry after content is present.
5. **Ambiguous transient upstream statuses are retryable, not permanent.** Before mapping a 4xx/5xx into a user-facing permanent claim ("no longer available", "deleted"), re-probe the same identifier later. If it can answer success afterwards, report a retryable failure ("did not return right now — try again"), never a permanent state.
6. **Live authorization probes: mint per-user tokens, attempt the write, read back.** Via the platform's auth REST: PATCH/DELETE another user's row as user B (then confirm the row is unchanged), list rows with `user_id=neq.<own-uuid>` (must be empty), read unpublished rows as anon, attempt ordinary-user writes to admin-owned tables (expect 401/403). Assert status AND unchanged state — row-level security commonly answers 200 with 0 rows affected.
7. **Live write tests follow the test-infrastructure hygiene rule above**: one unique marker per run, delete every marker row at start and end, re-query to confirm zero leftovers. Delete through the product's own UI (some entities open a confirm modal, others are immediate) so the destructive path is tested too.
8. **Password recovery is verifiable only up to the provider boundary.** The reset token exists solely in the emailed link (the auth store keeps only its hash), so the link-click → new-password → sign-in leg is `NOT TESTABLE` without mailbox access. Verify the honest subset — request through the real UI returns the provider's success and the app shows its confirmation state, expired/invalid links degrade honestly, the new-password form rejects a mismatch before any provider call — and report the emailed-link leg as unverified. Never mint or insert auth tokens to simulate it.
9. **A throttled deploy path must not stop the work.** When both the platform's deploy API and its webhook answer the daily cap, keep building and verifying on the local host against real data, and leave an automatic deploy trigger behind (a scheduled job that compares the served revision to `origin/master` and deploys when they diverge) so the work lands the moment the cap clears without a second manual pass. Let the trigger skip while a build is already in progress, or it burns the remaining quota on duplicate deploys; confirm the landing with the revision pin in step 1. If the repo has a second host with no deploy cap (a static Pages deployment alongside the platform, say), push the build there and hand the user that URL in the same reply as the verification — a user who cannot open the result cannot judge it, so invisible-but-verified work is read as no work at all. Verify the fallback host actually serves the NEW artifact (cache-busted grep of a marker string in the built CSS/JS) before offering the URL; its CDN can lag the push by a few minutes.

## Harness pitfalls (a broken harness produces false verdicts)

- **Check helpers must take awaited booleans.** An async IIFE passed as the verdict is a Promise — always truthy, so every such check mis-reports. Await inside the helper or at the call site.
- **`waitForSelector` resolves on nodes from EARLIER actions.** When asserting "a new answer/row/message appeared", capture the element count before the action and wait for the count to INCREASE — a bare selector wait succeeds instantly on the previous element and the probe reads stale state (and then 'fixes' working code). Pair with request-body/response capture for API-shape assertions.
- **node:test vm fixtures load a fixed module list**: a newly required module breaks every fixture test with a ReferenceError, and browser globals (`AbortController`, `res.headers.get`) may be absent in the sandbox while present in the browser — add new files to the harness's load list and guard product code with `typeof` checks. The failure presents as broken feature code, not a harness gap.
- **Write verdict semantics once and name the expected side** (`blocked` vs `accepted`); a flag whose happy value prints as BREAK will be misread every time.
- **RLS denials return `error: null` + 0 rows** — assert on rows affected (`.select()` and count), not error presence.
- **Short-label `has-text` is substring**: `has-text('Male')` matches "Female". Use exact text (`button:text-is(...)`) for short labels. `form button.last()` lands on in-form nav links — click the named submit button.
- **`textContent` never contains input VALUES** — assert on `inputValue()` for form state.
- **Replacing a form control breaks every suite at once** (native date input → custom grid). Immediately grep all suites for the old selector; for date grids use one shared `pickDate(page, daysAhead)` helper that navigates months then clicks the day.
- **Rolling fixture dates/slots** (`Date.now() + N days`, varied slot) keep re-runs from colliding with the unique constraints they are meant to exercise.
- **Long scripts go to files** and run with `node file.mjs`; giant inline one-liners/heredocs trip the command parser's blocklist.
- **Preview/dev servers die between sessions, and `nohup ... &` launched inside a foreground tool call dies when that call returns** — start long-lived servers through terminal background mode instead, and health-check (`curl -o /dev/null -w %{http_code}`) before any test run instead of assuming the port is live.
- **Landmark collisions break legacy selectors**: a second `<nav>`/`<main>` landmark makes old `locator('nav')` calls strict-mode ambiguous (silent timeout, not an error). Keep one landmark per role or scope selectors to the known container before adding page chrome.
- **`fullPage` screenshots composite fixed/sticky chrome at the capture edge** — "content clipped under the tab bar" findings are usually capture artifacts. Confirm with viewport-scoped bounding boxes before touching layout.
- **A blank page with zero `innerText` is a crash until proven otherwise** — check the console for render/hook errors ("Rendered fewer hooks...") before hunting data bugs; a React root crash blanks the entire app while navigation still 'works'.
- **A blank SPA shell is a URL-shape mismatch until proven otherwise** — serving a subpath-based build (Vite `base: '/repo/'`) from a different mount 404s its assets, and a hash route absent from the router (e.g. `#/g/:id` vs `#/gadgets/:id`) renders an empty page indistinguishable from a crash. Read the router's route table and the build's `base` first, mount local copies at the production base path, and count root children / check network 200s before touching app code.
- **Vision-model audits return plausible wrong findings** (placeholder text read as page content, `closest()` matching the element itself, mid-animation frames read as misplaced elements, marketing images' baked-in text read as DOM overlap). Verify each finding with a DOM/pixel-extent check before editing anything. They are also subject to a stale-read race: analyzing a screenshot in the same batch as the call that writes it returns the analysis of the PREVIOUS image, which then reads like a bug report against already-fixed code. Write the shot, let the write settle, and analyze in a later call.
- **Supabase RETURNING quirk**: `update(...).select()` can fail with a table permission error while the same plain `update()` succeeds (column-allowlist SELECT grants). Probe writes without `.select()`, then read back separately.
- **Reads through RLS/security-definer views with a service or anon key return zero rows silently** (`auth.uid()` is null) — read the base table from tests, or use the acting role's own client.
- **Automation silently blocked by required chip/select controls** (category/type pickers no text input fills) and exact-text selectors missing real labels (`Save` vs a longer label). Drive every required control; give flaky inline panels one retry on the DRIVE, never on the assertion.
- **An overlay whose pinned footer is unreachable, or whose click hits the element behind it, is usually anchored to an ancestor instead of the viewport.** An entrance animation with fill mode `both`/`forwards` on a page/root element freezes its end-of-animation transform (even identity), which makes that element the containing block for every `fixed` descendant — the sheet then sizes against the page and grows past the screen. Measure before resizing anything: compare the wrapper's `getBoundingClientRect()` to the viewport, run `elementsFromPoint()` at the unreachable control, and walk the ancestor chain for computed `animation-fill-mode`/`transform`. Fix at the source: page entrances animate opacity only, or use fill `backwards`.
- **A `flex-1 overflow-y-auto` body only scrolls when it can shrink below its content size** — give it `min-h-0` (and the sheet container `overflow-hidden`), or the pinned footer is pushed past the container's max-height and clipped.
- **Attribute-equality selectors silently match NOTHING when the attribute is omitted** — `input[type="text"]` misses a type-less text input (it is still a text input). Scope by container and tag (`form input`, `form button[aria-label=...]`) instead of attribute equality.
- **A session/role injection the app never consumes silently runs every scenario as the same user.** Verify the switch landed (avatar initials, a role-only element, or role-scoped heading) before trusting any role-conditional verdict; a "role B" run that never switched produces confident nonsense like asserting a staff picker on a patient screen.
- **Screen identity must come from the URL, not router state.** A detail screen seeded from `navigate(..., { state })` shows the wrong record on refresh, shared links, and back/forward. Derive the id from the query param, refetch on mount, and reject cached state that disagrees with the URL.
- **Duplicate keys in a JS config object override silently** (two `theme.extend.boxShadow` entries → the first vanishes with no error). Grep the config for the key before adding it; when a class "doesn't apply", confirm the BUILT CSS contains it before touching the component.
- **`.find()` renders one row where several exist.** Day views and slot lists keyed by time collapse concurrent entries to the first match. Render all matches — uniqueness is usually on (slot, resource), not the slot.
- **`divide-y divide-<color>` writes full `border-color` to `> * + *` at higher specificity**, silently killing side-specific accents (`border-l-primary-*` row bars) on every row after the first — the first row keeps its accent, which reads as data wrongness. Use side-specific colors (`border-b-gray-100`, `border-l-primary-600`) and drop `divide-*` when rows carry their own borders; verify with `getComputedStyle(row).borderLeftColor`, not pixels.
- **A global reduced-motion layer (`* { animation: none !important }`) freezes every CSS animation in browsers whose fingerprinting protection always reports reduced-motion (Brave).** Defeat it per-animation with longhand `animation-name/-timing-function/-iteration-count: … !important` plus `animation-duration: var(--x) !important` fed from an inline custom property — the `animation` shorthand with `!important` also pins duration to 0s !important, which beats any inline duration.
- **Press-drag-release outside a custom slider strands its drag offset and pause flag** (the element never receives `pointerup`), blanking the slides and freezing autoplay — and a back/forward-cache restore can resurrect the stranded state after reload. Fix at the source: `setPointerCapture` on pointerdown, a window-level `pointerup`/`pointercancel` safety, and a low-frequency self-heal interval that zeroes the offset when no drag is active.
- **Restarting a dev server silently kills every open tab's HMR socket** — the user's browser keeps running old half-migrated modules and every fix appears not to work. While a human is viewing the app, serve the production build (`vite preview`) on their port instead of the dev server, and verify claims against the deployed/previewed bundle (marker strings + behavior probes), not against your own fresh headless page.
- **An anonymous REST/PostgREST probe must OMIT the `Authorization` header entirely.** Sending `Authorization: Bearer ` (empty) answers `PGRST301` JWT-invalid, which reports as an authz failure in the matrix when the endpoint is actually wide open (or correctly gated for a different reason). Only send the header carrying a real token.
- **Top/bottom overlap math cannot see vertical clipping inside a box.** `getBoundingClientRect` showing a gap between a text block and the next row reports "no collision" while the text is sliced mid-glyph by its own `overflow: hidden`. On every clamped or fixed-height text block also compare `scrollHeight` to `clientHeight` — a larger `scrollHeight` means lines are being cut regardless of what the neighbour geometry says. The mirror trap: a vision audit reports overlap from marketing images whose baked-in text is not DOM at all, so confirm any collision against rects, not pixels.
- **Confirm which build artifact your verification server actually serves.** Multi-target repos emit different outputs per target (static-hosting `docs/` vs platform `dist/`, often only one of them built without a flag), and a probe pointed at the wrong one reads every correctly-authored source change as "did not land" — which sends you back to re-patching working code. Read the build script's `outDir` and what sets it before chasing a change that appears unapplied.
- **A suite gate can encode a standing product decision, not just presentation copy** ("no quick-actions card on owner home — nav is the surface", "financials are owner-only"). When a new feature trips such a gate, replace the feature at the product level (data-driven card instead of nav duplication; role-gated values) — never weaken the assert to bless the addition.

## Acceptance gate + report

When the user asks to review before deploy: commit locally and stop — no push. This user's standing default for fix/mission work is the opposite: drive to deployed-and-verified — QA, verify, then deploy; commits and checkpoint notes are the milestones, not progress questions, and "don't stop until it's all done" is literal. Evidence-only reports throughout: every "done" carries executed test output and, for UI changes, before/after screenshots; "looks good" without a run is not a report.

Report shape: what was tested (per role / cross-role / backend / design) · what was fixed as a **before → after table** (area | before | after), each row carrying its regression evidence · remaining blockers (genuine only) · final results table (PASS/PARTIAL/BLOCKED/NOT TESTABLE) · the executed live-demo scenario · known limitations (state them, never hide). Close with explicit delivery state: what is committed / pushed / deployed vs still in the working tree. A run is evidence only for the tree it ran on — any edit after the last run means re-run before reporting. When fixes change what release docs assert (counts, versions, migration numbers), reconcile the docs in the same pass and mark superseded numbers as historical; mixed stale and current claims read as fabricated. Severity: **P0** security/data corruption/impossible workflow · **P1** major feature or cross-role breakage · **P2** meaningful UX/data issue · **P3** polish. Bug entries: role, screen, severity, precondition, repro steps, expected, actual, reference expectation, DB behavior, cross-role impact, root cause, recommended fix.
