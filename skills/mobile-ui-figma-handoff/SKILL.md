# Mobile UI → Figma Handoff (single-file HTML)

## When to use

- User asks for a mobile UI design deliverable and wants to put it in **Figma** ("html for figma", "so i can put it on figma", design screens for a capstone/proposal).
- Design-review artifacts where the user pastes screenshots or uses html.to.design.
- **User preference (Attila):** for these deliverables he wants self-contained HTML with fixed phone frames — NOT a React/Vite app. A React scaffold for the same ask is dead weight. Default to HTML; only build the app when explicitly asked.
- **DELIVER AS SEPARATE FILES (one screen per `.html`), not one big board** — verified 2026-08-12: html.to.design drops overlay states (dialogs, bottom sheets, toasts) from single-file boards, and the user hit it twice then explicitly asked for separate files ("not one whole html i want separate so its clear because when using the one html some are gone like dialogs"). A one-file board is fine as an overview, but the import path is per-screen files. Split with a script (extract each `.frame-wrap`, keep the shared `<style>` + SVG sprite per file).
- **Merged single-file is safe AFTER the scrim-free rebuild** (verified 2026-08-13): once every frame is pure static flow, stack all screens in ONE html and it imports clean — the old multi-frame drops were overlay-caused (absolute/transform + rgba scrim), not multi-frame-caused. The user's final preference: deliver BOTH — the numbered folder of separate files AND `NN_Name_All_<N>.html` for one-shot export ("merge them so i can just export 1 html file in the figma"). Merge recipe: one shared head (base CSS + edge CSS + ONE sprite — dedupe; duplicate symbol IDs are harmless but wasteful), each frame preceded by a `.frame-label` ("01 · Login"), all inside a `.board` flex-column wrapper (margin 24px auto). Use `scripts/merge_frames.py <dir> <out.html>` — it dedupes head/sprite and self-verifies: frame count == label count, each frame exactly 390×844, y-sequential, zero x-overflow inside frames, all `<use href>` refs resolve.

## Deliverable contract

- One `.html` file, **zero external dependencies**: no CDN links, no webfonts (system stack), no external images. All icons = inline SVG (lucide-style paths, stroke 2, `currentColor`).
- Every screen = a `.frame` div, fixed **390×844** (standard phone), `overflow:hidden`, labeled with a `.frame-label` OUTSIDE the frame ("01 · Login", "02 · Register", …) so Figma importers get clean named frames.
- Include state screens as separate frames: dialogs open, bottom sheets open, toasts, role-variant pages (e.g. student vs driver profile) — reviewers want the states, not just the happy path.
- Design language (this user): flat, single accent `#5e6ad2` periwinkle, borders over shadows (no `shadow-*`), no gradients/pills/badges/glass, 44px touch targets, inputs h-44px, cards `rounded-lg`, light mode only (outdoor readability), 16px gutters.
- Write a `DESIGN.md` alongside when the brief is product-sized: palette tokens, type scale, component list, page-by-page requirements. It is the OpenDesign substitute when the OD app is not installed (see opendesign-headless).
- Source content from the actual requirements doc, not generic lorem: real device names, prices in ₱, real roles/statuses from the product purpose.

## Workflow

1. **Extract the brief** — `.doc` binaries: try `antiword`, and if it fails (WPS-created OLE2 files), use the UTF-16LE recipe in `references/doc-extraction.md`.
2. **Design system** — tokens + component spec (see contract above). Reuse the `#5e6ad2` flat language; do not invent a new style per project.
3. **Write the HTML** — frames 01..NN, one `<style>` block with utility classes (`.card`, `.btn-primary`, `.field`, `.nav-item`, …), inline SVGs only.
4. **Render + screenshot** — Playwright: `page.goto('file:///...')`, viewport `{width:500, height:20000}` (**tall viewport required** — clip coordinates below the fold throw "Clipped area is either empty or outside the resulting image"), then per-frame `page.screenshot({clip})` using `getBoundingClientRect()` coords. Output to a `qa/` folder.
5. **Vision QA** — if `vision_analyze` fails (provider rejects image payloads), call OpenRouter directly — key in `~/AppData/Local/hermes/.env` under `OPENROUTER_API_KEY`, model `qwen/qwen-2.5-vl-72b-instruct`, image as `data:image/png;base64`. Prompt: report ONLY concrete issues with severity + location, else reply exactly `CLEAN`.
6. **Verify flags with geometry** — vision models hallucinate on dimmed/overlay screens. Before fixing a flagged issue, measure real bounding boxes via Playwright `evaluate` (avatar vs text overlap, element right-edge vs frame right-edge). Only fix what geometry confirms.
7. **Tag-balance check** — count opens vs closes per tag (`<div` vs `</div>`, etc.). A stray closing tag is a real, silent layout bug: one `</span>` closing a `<div>` nested the contact text inside a 32px avatar circle while everything *looked* right.
8. **Fix → re-shoot → re-QA the changed frames only.** User's standing rule (2026-08-13): **visual-QA the complete set every time** — run a full vision pass over ALL delivered screens without being asked; per-change passes during iteration, full-set pass on the final deliverable. Deliver the QA table (verdict per screen, flags investigated with geometric proof).
9. **Edge-case sets ("every state of the app")** — build a numbered folder (`01_…`, `24_…`, one file per state): proven frames copied VERBATIM (don't touch what imports fine), broken frames rebuilt scrim-free, plus the state screens reviewers check — login/register error, forgot-success, home empty/offline, no contacts, no user type. For multi-role apps add the full account-lifecycle set: register role-select, pending-approval screen, login-blocked states (pending / rejected+reason / disabled — one frame each), activated-welcome, owner approval queue, reject-with-reason, permission editor, restricted-staff-view. Every lifecycle state = its own frame; one `blocked_login(msg, tone)` template generates all blocked variants. Generate with a small Python script: one file's `<style>` + SVG sprite as the shared head, per-file bodies in a dict (see `gen_edge.py` pattern). Never hand-copy the CSS between files. After generating, run `scripts/fitcheck.js <dir>` (vertical-fit + frame-origin check).
10. **Polish pass ("reaudit and fix until it looks polished")** — run a dedicated critique pass (vision prompt: "list concrete polish defects ONLY, max 3 bullets") over the NEW screens, then treat the output as HYPOTHESES: vision critique is low-signal (it flags "spacing inconsistency"/"awkward empty space" on nearly every screen, mostly design-taste noise). Fix only what geometry or the design language confirms:
    - **Floating dialogs** — a dialog floating in whitespace looks detached; center it in the remaining space with a `flex-1` wrapper (`display:flex; align-items:center; justify-content:center`) — NOT pushed to the bottom by a bare spacer.
    - **Frames ending on a secondary element** (orphaned link after the CTA) — reorder so the frame ends on the primary button.
    - **Half-empty frames** (content ends ~400–500 of 844) — fill with real content from the sibling happy-path screen, then trim (drop rows) until `scrollHeight <= 844`.
    - Ignore: "button not distinct enough" (accent-on-light IS the design language), secondary-vs-danger button contrast (intended hierarchy), bottom whitespace on content screens (standard for design frames), status/check alignment (flexbox-centered by construction).
    Re-shoot + full-set QA after every fix batch.
11. **Derivatives (prototype / wireframe)** — the static frame set is the source for both, WITHOUT touching the originals:
    - **Clickable prototype** (user: "when you click this part you will go to this part"): annotate hotspots with `data-nav="NN"` (stdlib HTMLParser mini-DOM, exact text match for buttons/links, CONTAINS for rows/cards, card keys ordered before contained button text), one delegated click handler toggling frame visibility + a current-screen badge. **Never use `!important` on the display rules** — it beats the JS inline styles and the prototype silently never navigates. Verify with a Playwright click-through (assert visible frame id per step), not screenshots.
    - **Wireframe** (low-fi gray): one extra `<style>` block redefining the `:root` color variables to grays + `!important` overrides for hardcoded banner colors and inline-styled avatars. Zero body changes; verify by computed style.
    - Full recipe + pitfalls: `references/prototype-and-wireframe.md`.

- **Role-adaptive single app**: when the product has owner/staff/customer roles, build ONE frame set where the nav is a parameter (`nav(active, staff=True, income=True, req=0)`) and role visibility = rendering differences, not separate apps. Owner nav shows everything (6 tabs OK: Home·Calendar·Requests·Patients·Income·Staff); staff see the same nav minus owner-only tabs; **patients get their OWN 5-tab navbar** (2026-08-14 user: "make sure they still have a good navbar icons" — Home·Appointments·Book·Messages·Profile via a `nav_patient(active)` helper), not a bare header. Add ONE frame showing each restricted view (e.g. staff dashboard without Income/Staff tabs + a "hidden modules" banner) — reviewers ask for it ("not visible to them"). Changing the nav = one function + `replace_all` on call sites (see replace_all footgun in Pitfalls).
- **UX council via delegate_task**: for deep user-flow/IA questions ("think it through", multiple modules), fan out 2–4 leaf subagents with self-contained context (~1.5K tokens each: project brief + design system + the question + "terse markdown, max 500 words, no code") and synthesize into frames. Hard limit: **each delegate_task call must stay under ~8K tokens or the stream times out** — split 4 tasks into 2×2 batches. Subagent summary files can arrive mojibake/`read_file`-flagged binary: decode raw with `open(p,'rb').read().decode('utf-8', errors='replace')`. **A batch's consolidated result can get dropped entirely** (completed at T, never re-entered the conversation): recover from the live transcripts at `~/AppData/Local/hermes/cache/delegation/live/<deleg_id>/task-N.log` — append-only logs where the final line is `final | status=completed ... summary: <full text>`; extract with `text.rfind("summary:")`. Build council-independent frames (patient lists, CSS primitives) while waiting.
- **Deep-QA script**: after generation run `scripts/qa_deep.py [frames_dir] [NN...]` — one pass detects squished buttons (<34px), x-overflow, body overflow (clipped-behind-nav), and >140px voids. Run on the FULL set before delivery, not just new frames (nav/component changes propagate). On this machine invoke it with the absolute Python (`C:/Users/YOUR_USERNAME/AppData/Local/Programs/Python/Python311/python.exe`) — bare `python` resolves to a Hermes-venv interpreter without playwright (PYTHONPATH leak). Same for any Playwright QA: big heredoc-in-terminal QA blocks also hit stream-size timeouts — write the script to a file, run by path.
- **Zero-flaw loop** (user: "loop until you don't find a single flaw"): run the ladder to convergence — `qa_shot.py` geometry + `qa_deep.py` + `scripts/audit.py` (static: tag balance self-closing-aware, `<use>` refs, CSS braces, hardcoded colors vs token whitelist, leaf-text overflow, PNG md5 uniqueness) + merged-board browser check — fix everything flagged, re-run until all-zero. When the user demands zero flaws, even the login/hero whitespace frames (normally exempt, see flex-squish pitfall) get filled with flow content (contact/reset/hours banners, recent-activity cards, next-steps cards) until voids < 140px.
- **Story-consistency pass (multi-frame decks)** — the #1 source of "the flow feels off" in a 50+ frame deck is not layout, it's STORY drift: frames appended over many turns contradict each other (one patient with two appointments, a dentist who is both active staff and pending approval, three different "today" schedules). Fix pattern (verified 2026-08-14, 28 story inconsistencies found by a 4-agent audit council):
  1. Write ONE canonical story in DESIGN.md: today's date, every persona (active staff vs pending registrant vs invited = DIFFERENT people), the patient's full visit history with amounts, today's schedule, all KPIs and their arithmetic (avg = total ÷ txns).
  2. Audit every frame against it; when a value must change, change it EVERYWHERE (grep the generator for the old name/amount/date and sweep).
  3. Add NEGATIVE checks to `scripts/audit.py` — assert removed concepts appear NOWHERE (`GCash`, `Outstanding`, `preferred`, `slot online`). When a feature is removed and an old positive check fails, INVERT the check to assert absence; never just delete it — that's how regressions leaked.
  4. Reorder the FRAMES list to the FINAL deck order the user settled on (2026-08-14, iterated 4× — interleaved A–F rejected, role-first journey rejected for splitting dentist story across sections): **① login/register + validation** (welcome, both logins, login errors, forgot pw, role select, both registers, register errors, dentist approval lifecycle) → **② Patient** (happy path + notifications) → **③ Doctor** (dashboard → calendar → requests → completed → patients list → record → note/edit/attachment → staff view → notifications → settings) → **④ Owner** (income module → staff module → settings) → **⑤ Empty counterparts** (ALL edge/empty states grouped last). The user's rule: all auth+validation up front, then per-role happy paths, empties at the very end. NOTE: auditor subagents that `ls` the frames directory see ALPHABETICAL order and will judge a stale arrangement — when dispatching ordering audits, paste the explicit deck order into the task context, never point them at the directory.
  5. **Feature-removal sweep** (user: "there should be no X feature"): archive the frames (`mv frames/NN_*.html frames/archive/`), remove them from FRAMES, then grep the generator for EVERY reference — entry buttons, KPI rows, banner copy, notification rows, canonical-story lines in DESIGN.md — and replace with the surviving flow (e.g. invite removed → staff list button becomes "Review Approval Queue", queue shows 2 self-registered dentists, banner "staff join by registering on the web app"). Then update the canonical story and add/reuse a negative check for the removed concept. Same rule for **manual-add features when registrations auto-populate the list** (user: "why is there an add new patient… it will just load everyone who registered as patient"): delete the Add screen AND the Add button, replace both with a banner ("New patients appear here automatically once they register on the portal").
  6. **Nav-coverage rule**: every screen reachable from a bottom tab carries that tab's nav — including edit forms, add-attachment dialogs, and detail views inside a module (user: "some frames lack the navigation"; 55/56 shipped without nav until flagged). Exempt only auth, pre-login lifecycle states (pending/rejected/disabled/activated), and settings. Trimming fields/banners to make room for the +64px nav is correct.
  7. Collapsed-render probe: if qa_deep reports a huge void (>300px) on a frame whose source looks complete, count `<div` vs `</div>` inside its body and depth-walk to the first negative index — a stray closer from a patch/revert collapses the rest of the layout (nav renders below the 844px fold; Playwright shows `navTop ≈ 844`). Full recipe: `references/canonical-story-consistency.md`.
- **Guardrail-compliant renames**: never `rm` a renamed/stale frame file — `os.replace()` it into `frames/archive/`, and `os.replace()` the merged board when the frame count changes (`All_36.html` → `All_60.html`). Same for moving regenerated deliverables: rename, don't delete.

## Pitfalls

- Screenshot clip outside the viewport errors — always use the tall viewport.
- **Vision fallback can flip mid-session to a route that rejects `image_url` entirely** (observed 2026-08-14: contact-sheet QA succeeded 3×, then every later call failed with "unknown variant `image_url`, expected `text`" from the Console Go fallback; OpenRouter qwen-vl 402 out of credits). Retry once or twice (it recovered before), but don't block delivery on it — geometry (rect size, scrollHeight, overflow, content-bottom vs nav-top voids) is the authoritative check and covers the common defects (clip, overflow, half-empty). Ship with a QA table noting which screens were vision-verified vs geometry-verified if the provider stays down.
- **PIL pixel-edge sweep as the vision substitute** (verified 2026-08-14, full 63-frame pass): per-frame PNG, scan for non-background ink within 2px of each edge (left/right/bottom). Two false-positive classes to whitelist BEFORE flagging: (a) the frame's own 1px border (`#e2e8f0`-ish gray, delta-tolerance ±10) and (b) full-bleed design bands like a teal `.login-hero` (by-design edge-to-edge) — if ALL frames of one header type flag, it's the band, not clipping. Pair with an md5 uniqueness sweep over the PNGs (byte-identical siblings = dropped content). Run this after every full regeneration; it catches clipping geometry QA can't see. Same tool works on a **Figma screenshot** to diagnose imports: downsample to a coarse brightness map (PIL, ~40px grid, `#`<60 `<`' '.', `>`200, `.`>`140`) — a dark Figma canvas with one white band + scattered dark text = frames imported WITHOUT their white backgrounds (backgrounds/overlays lost); interpret bands vs scattered text before rebuilding.
- **`replace_all` and big multi-line patches are footguns** (2026-08-14): `replace_all` on `{nav("cal")}` silently flipped 3 calendar frames to the wrong tab, and one multi-line patch dropped a `return` statement (old/new anchor mismatch), breaking the function until read+repair. After ANY replace_all or >5-line patch: run the generator + linter immediately; don't stack more edits on unverified state. When multiple frames legitimately share an anchor string, use per-function unique context lines.
- **Flow-completeness pass (deck-level, before final delivery)**: trace every tappable element to a destination frame — bell badge → notifications screen (per role), every ghost/danger btn → its dialog state, "Add X" → its form, avatar → settings (staff variant too), logo/back → parent, KPI/quick cards → their section. This pass found 5 dead ends in one session (bell, decline, add-patient, staff settings, upload-proof entry). Every "what happens if…" a reviewer can ask must resolve to an existing frame. Council-verified details (2026-08-14): auth screens (login/register/role-select) get a back arrow to Welcome; shared utility screens get role-neutral copy (ONE Reset Password screen serves patient+dentist — don't duplicate per role); list rows get per-status actions instead of identical chevrons (pending→Review, deactivated→Remove, active→chevron-to-manage); offline banner pairs with a Retry button; completed appointment rows get a Receipt action, pending/cancelled get none.
- **Settings must be discoverable AND carry a navbar** (user: "how the hell can you access the settings and it doesn't have a navbar in the owner settings"): put a gear icon-btn in the PWA header next to the avatar (dashboard frames incl. empty state) → opens Settings; give the settings screens themselves the role's bottom nav. Patients don't get a gear (profile tab is their settings).
- **Grouped status lists beat one flat mixed list** (user called the flat staff list "very chaotic"): section the list by state — "Pending approval" (row + Review), "Clinic team" (active rows + chevron/manage), "Deactivated" (muted rows + Remove) — each section its own card + small-t header. Per-status row actions live INSIDE their section, not as mixed buttons on every row.
- **OD-exported standalone frames carry stray wrapper `</div>`s that corrupt the merged board** (verified 2026-08-14: 709 stray closers across 24 frames; symptom = one frame's content swallows every later frame, `deep` reads 3398, later frames measure h=0 inside the first frame's `overflow:hidden`). Cause: `merge_frames.py`'s lazy `frame_div` regex captures everything up to the LAST `</div>` before `</body>` — OD files end `</div></div></div></body>` (frame close + board/wrap closers). Browsers auto-repair the DOM so previews look fine, but html.to.design trips on it. Fix BEFORE merging: `scripts/normalize_frames.py <dir>` — for each file, balance-walk from `<div class="frame"` to depth 0 and rewrite the file as head + exactly-one-balanced-frame-div + fresh tail. Re-run it after ANY body-splice edits to overlay frames (string-surgery loses closers). Verify the merged board with a token walk: zero `</div>` at negative depth, all 29 frame divs close clean.\n- **Merging a PREBUILT external frame set** (user hands over an existing NN_Name.html folder from another tool/session: per-file `<style>`+sprite, `data-od-id` divs, no frame-wrap wrapper, often CRLF). The generator-oriented `merge_frames.py` doesn't fit these; use the extraction recipe in `references/merging-external-frame-sets.md`. The two silent killers: (a) the frame-extraction regex `(<div class="frame".*?)\n\s*</div>\s*</body>` eats the frame's OWN closing div, so the wrapper must append TWO closes or the browser nests every subsequent frame inside frame 1 (innerHTML explodes, children counts still look normal, html5lib and Chromium can disagree — trust the browser probe); (b) each file's sprite is incomplete, so the merged board must UNION all `<symbol id>` defs or `<use>` refs break. Verify with a Playwright probe: per-frame size, unresolved-use count, innerHTML length, nav Y/N map. Also: if the deck lacks the product's defining interaction (a distress-button app with no alert-fired screen), ADD that one frame — reviewers notice the hole before any polish issue.
- **OpenDesign single-file board → standalone frames** (user hands over ONE html containing all frames: `<!-- NN · name -->` markers, `.frame-wrap`/`.frame-label` wrappers, inline SVGs, NO sprite). Reverse of merging: `scripts/split_board.py <board.html> <out_dir>` splits on the marker comments with a balanced-div scan and derives `NN_Name.html` from the comment text; then run `scripts/merge_frames.py frames All_N.html` on the project copy (merge script's `sprite()` now tolerates sprite-less boards). Wireframe for a board whose CSS you didn't author = one appended style line, `filter:grayscale(1)` on `.board .frame` — no `:root` rewrite needed. QA: measure per-frame depth RELATIVE to the frame rect (`r.bottom - fr.top`; absolute rects shift when the page auto-scrolls — body can sit at y=-40) and use the ORIGINAL board's per-frame depths as the ceiling, not 844 — scrollable screens (About, profiles) legitimately run 1000–1700px deep and are clipped by `overflow:hidden`; only flag what exceeds the original. Merged-board check is `scripts/qa_board.py <board.html> [ceiling=1700]` — one Playwright pass over all frames, no per-file setup. Copy `qa_deep.py` into the project and pass the frames dir explicitly (its default dir is relative to the script's PARENT, which breaks when the script sits in `design/`).
- **STALE-SOURCE CHECK FIRST** (user: "it contains the latest and fixed versions right?" — caught a 13-frame merge when 24 frames existed): Downloads/project can hold several generations of the same deck (`UI.html` 13 frames, `UI_All_24.html`, `UI_Edge/` split dir, `UI_Prototype.html`, `UI_Wireframe.html`). Before merging, `ls -la` all candidates and compare mtimes AND frame counts (`grep -c "frame-label"`); pick the newest, and prefer an already-split `*_Edge/` dir over a lone older file. Verify the fixes landed in the chosen source (grep for the known-bug signature, e.g. the stray `</svg></span>`). Delete stale outputs from the project after re-merging (`All_13` → `All_24`) so the user can't import the old one.
- **Adding missing frames to an external board** (user: "add those, I want every edge case"): clone-and-swap — `head = template.split('<div class="frame"', 1)[0]` from the NEAREST sibling frame (same header/no-header shape), rewrite only `<title>` + the body block, keep the sibling's exact FRAME_OPEN div and tail (`\n        </div>\n</body>\n</html>`). One dict of bodies → N files; 5 frames added to an OD-style board this way merged and QA'd green first try. Pick the template by structure: full-screen state (no header) vs screen with back-header vs form.
- **Edge-completeness checklist** (user asks "every edge case is there right?"): audit against the BRIEF, not intuition — (a) every named proposal feature must be a frame (false-alarm cancel window = arm→countdown→cancel + cancelled-confirmation states); (b) per FORM: success state existing does NOT imply the error state exists (forgot-success was shipped, forgot-error wasn't); (c) per ACTION: scanning state existing does NOT imply the failure branch exists (pair-timeout); (d) per LIFECYCLE: full loop for the defining interaction (press → countdown → send/cancel → dispatched/cancelled).
- **New icon names must exist in the sprite** — `ic("refresh")` with no matching `sym("i-refresh", …)` fails the merge assert (`unresolved use refs`). Grep the sprite for the id before using a new icon; adding one is a single `sym()` line (lucide-style path, stroke 2, `currentColor`).
- **User preference: "What happens next" = connected-circle stepper, not kv rows** (2026-08-14, "like the other professional dashboards"): `(1)──(2)──(3)` with 28px circles on 2px connector lines — current step teal-filled, done steps green, labels 11px below. One `steps(items, on=n)` helper generates it; apply to booking-confirmed, forgot-password, pending-approval, invite-sent, activated-welcome, and any empty-state "how it works" cards.
- **Flex-shrink silently squishes buttons/cards when `.body` content overflows** (found 2026-08-14): `.body` is `display:flex;flex-direction:column;flex:1`, children default to `flex-shrink:1`, so an overflowing Export button rendered 22px tall instead of 44px, clipped behind the bottom nav — vision QA called the screen CLEAN and the frame-level overflow check still passed (clipped children's rects hide inside `overflow:hidden`). Detection scan for EVERY full-set pass: per frame evaluate `body.scrollHeight - body.clientHeight` (>0 = clipped) AND every `.btn/.slot/input` rendered `height < 34` (= squished). Fix by trimming one row/card above the button (~31–64px each); the button springs back to 44px. Void measurement (last body child bottom vs nav top) only applies to nav frames and content screens — login/hero screens with bottom whitespace are standard and vision-approved, don't "fill" them.
- Vision "CLEAN" on 12/13 frames with 5 flags on one: don't fix all 5; geometry showed 4 were perception noise from the scrim overlay.
- Tag imbalance is invisible to vision QA — the grep/python count is the cheap catch.
- html.to.design imports full pages; keep labels and frames as siblings, never nest the label inside the frame.
- **Overlay states must be STATIC FLOW layout, never `position:absolute`/`transform`** — html.to.design drops absolute+`transform:translate(-50%,-50%)`-centered dialogs/sheets on import (they render as byte-identical plain backgrounds in Figma). Fix verified 2026-08-12: scrim = in-flow flex area with `rgba` background, modal centered via flexbox (`display:flex; align-items:center; justify-content:center`), sheet bottom-anchored via `justify-content:flex-end`, toast in normal document flow. Plain absolute offsets (e.g. `top:16px`) DO survive — the transform centering is the killer.
- **Drop the rgba scrim entirely** (verified 2026-08-13): even the in-flow `rgba(17,24,39,0.45)` dimming block (previous fix) STILL imported as a black screen for this user. The fully import-safe dialog/sheet = a flat card sitting directly on the light page background — page content above (undimmed), `.dialog-card` below centered via flexbox, sheet = bottom static card with a handle, toast = in-flow bar. No dimming anywhere. Design dialogs as flat compositions; importers handle light-background cards reliably.\n- **OD/absolute-overlay frames: THREE failure modes, escalate in order** (verified 2026-08-14, Guardian Alert 29-frame deck):\n  1. **Inline `position:static` on the frame div leaks overlays across the whole merged board.** OD exports add `style=\"display:flex;flex-direction:column;position:static;\"` to frame divs, which beats the CSS `.frame{position:relative}` — every `.scrim{position:absolute;inset:0}` and sheet then anchors to `<body>`, so each scrim paints over ALL frames in the board (frame 05 looked \"blackened\" = 4 stacked scrims). Fix: `sed -i 's/position:static/position:relative/' *.html` over the frame set, re-merge, then verify with a containment probe (Playwright: each `.scrim/.modal/.bottom-sheet/.toast` rect must lie inside its own frame rect — zero leaks expected).\n  2. **html.to.design imports the scrim but drops the absolutely-positioned sheet** (user screenshot: black rectangle, no sheet). `absolute; bottom:0` sheets fail even though `absolute; inset:0` scrims survive — assume ANY absolute overlay in a sheet/dialog frame is unreliable. Static conversion that preserves the visual: wrap the underlying screen in a **dimmed crop** — `style=\"height:264px;overflow:hidden;opacity:0.55\"` (opacity on in-flow content imports fine, unlike the old rgba scrim div) — and render the sheet/dialog as an in-flow `.sheet-static`/`.dialog-card` below it.
