# Product Site Design (static, Figma-bound)

The deliverable is always a static site Attila will reproduce/import into Figma (prototypes = visual contracts). Optimize for hierarchy, spacing, typography, realistic product UI, and clean import — never for motion or effects.

## Standing direction (applies to every build)
1. **Real product company, never AI concept page.** Do not promote a metaphor (instrument station, nautical, terminal) to the whole visual personality. Borrow 2-3 characteristics, simplify. One signature concept per site max.
2. **~4 palette roles with dominance**, not one narrative color per section: warm off-white foundation (majority), primary dark (hero/footer/authority), ONE loud accent (CTA/key data only), gray for borders/muted text. A section's topic never earns it a new color. Severity/risk states = typography + weight + contrast, never extra hues.
3. **Zero fake telemetry.** No timestamps, unit IDs, AUTO-ON/LIVE lamps, window dots, status pills, floating label cards in mocks or chrome. At most ONE real measurement in the hero visual (e.g. '38/100'). State lists = plain quiet text.
4. **Mono = measurements + row index numbers only.** Labels/captions/footers/eyebrows = normal text.
5. **No em dashes in visible copy** — rewrite as two sentences or commas (meta/OG tags exempt). Benefit-first, natural product-team voice, no invented capabilities.
6. **Static/Figma-safe:** no animations, transitions, hover-dependent info, video. Radii: 8px controls, 12px cards, one 20px showcase. Flat elevation (shadow only on the one hero showcase panel).
6b. **Solid surfaces only — zero CSS gradients** on any brand surface (hero, CTA, footer, cards, charts). Depth comes from flat contrast steps, borders, and spacing; a gradient hero is the single most-cited 'AI-generated' tell in audits. Fixed chrome hidden when empty uses `display:none`, not transform offsets (full-page captures paint the leftover sliver).
7. **Editorial structure over card grids:** Hero -> Problem (numbered hairline list) -> Solution (alternating product rows) -> How it works (3 steps) -> Features (grouped 2-col list) -> Where it lives -> CTA. Product-as-hero: device render + one clean app screen.
8. **Honesty stays:** prototype/disclaimer lines and honest-drawbacks comparisons are a feature (trust), not clutter — keep them even when polishing.
9. **One data story across every product surface.** All device/dashboard/app mocks on a site share room names, status vocabulary, and the same numbers. An auditor will flag a surface saying "Watch" while its siblings say "Elevated" — unify the vocabulary before shipping.
10. **Removal test for polish passes:** "If I removed this element, would the visitor lose information, or would the design simply become cleaner?" Cleaner = remove. Never add content to fill whitespace; stop once the design is coherent.

## Scope docs are subtraction contracts
When Attila supplies a scope/requirements doc for a build ("check this is the scope"), audit the site AGAINST the doc and REMOVE everything beyond it — do not treat doc items the build lacks as gaps to fill and never start adding them. The doc defines the feature set exactly; out-of-scope extras (bonus pages, moderation powers, fabricated metric panels) are defects to delete. Sweep each removal fully: nav/sidebar links, JS router maps, store/API functions, test assertions, copy that references the removed feature, orphaned icon entries, column counts in shared table markup. Then verify: node test suite, headless E2E over every admin/public page with zero console errors, and the live URL (deleted pages must 404; grep the live JS for removed symbols — GitHub Pages CDN lags 2-3 min, cache-bust and re-check).

The doc is the ceiling AND the floor, but it is not scripture: when Attila challenges a doc item ("why is X here / we don't handle that"), that is a removal verdict, not a discussion prompt — answer the why in one line, then cut the feature in the same pass as any trim. A mid-task correction supersedes the doc; re-derive the feature set from the user's product model (who owns which responsibility), not from the original text. Removing a feature must not take its public-side read-only view with it — cut the management surface, keep the user-facing visibility.

## Admin-console scope (GadgetWise, fixed)
The admin area owns exactly: gadget CRUD (add/edit/delete, specs, mock product-API prefill), category CRUD, review moderation (approve/edit/reject), and view-only stats (users, gadgets, reports). It does NOT manage: reported issues (public-side info only — detail-page tab + report form), user accounts (no suspend/activate), data-quality audits, or export/import. When touching admin pages, preserve this boundary; new admin powers beyond it are defects.

## Procedure
1. Read the project's DESIGN.md / PRODUCT.md / claim register before writing copy (claims frozen; new capabilities are forbidden without a source).
2. Build/rebuild page(s) on shared tokens (site.css `:root`); page-scoped overrides via `<body class="page-x">` + `.page-x` selectors, appended CSS, never renames of classes other pages use.
3. Serve locally (`python3 -m http.server PORT`), then Playwright QA every page x viewport (1280x800, 390x844): scrollWidth <= viewport, 0 console errors, all internal links resolve, anchor targets exist + `scroll-margin-top` on sticky-header anchors, no `transition:/animation:` additions.
4. Copy sweeps (visible text only): em dash, UNIT/timestamps/AUTO-ON/LIVE, banned classes (`chip`, `lamp`, `kicker`, `hero-tag`, `statline`, `specline`). No kicker/eyebrow above any heading — ever.
5. One vision pass scoring ONLY 'brand maturity: looks like a real product company' with defects + positions; fix batch; one re-inspect. Stop polishing after that.
6. If a Figma board file exists, regenerate it (see reference) and verify it the same way. Commit + push + curl-verify the live URL before reporting done.
7. Vision audit procedure (when the user asks to 'visually audit the UI'): shoot live full-page screenshots at 1440x900 AND 390x844 of every major page (Playwright chromium; see QA pitfalls for capture artifacts), run 1-2 vision passes with section-level questions, then DOM-adjudicate every finding with computed styles / getBoundingClientRect before editing. Fix, re-shoot, one confirm pass. Two delivery rules: the user reads English only — vision models sometimes answer in another language, so rewrite ALL vision output into English before it reaches a reply (never quote CJK fragments); and one giant full-page PNG can time the vision call out — prefer viewport-clipped or per-section shots when a page is long.

## QA pitfalls (mechanisms, not anecdotes)
- **Overflow checks miss squeezed layouts.** A base rule defined AFTER a `@media (max-width)` block wins the cascade at equal specificity and silently cancels the stack — the grid stays 2-column on mobile with zero overflow to flag. Assert computed `grid-template-columns` count per viewport (2 desktop / 1 stacked), not just scrollWidth.
- **Full-page screenshots misplace sticky headers** — they paint at the capture scroll offset, so vision models report "header collides with content mid-page" that does not exist. Adjudicate EVERY vision geometry claim with DOM rects (getBoundingClientRect + scrollY) before editing anything.
- **Fixed-position chrome also paints mid-page in full-page captures.** Compare trays, toasts, and cookie bars (`position:fixed`, near-black backgrounds) render at the capture offset and read as a "stray black band / off-palette stripe" through the whole audit. Enumerate `position:fixed/sticky` elements and their computed backgrounds before accepting any stray-band finding. Hide empty fixed chrome with `display:none` (show = `display:block` + entrance animation), never `transform: translateY(110%)` — a transform only shifts the element by its own height, so a full-page capture still paints the sliver that pokes out, and every screenshot pass re-flags it.
- **Icon-left inputs and same-hue CTAs fail invisibly to functional tests.** An input's padding-left must cover the icon gutter (offset + width + gap) or the icon overlaps the placeholder — only screenshots show it. A primary button fails when its fill is the SAME hue as its surface (indigo fill on indigo hero reads disabled); the fix is contrast, not mandatory white — a brand fill ≥3:1 against a dark hero surface passes (e.g. electric blue on blue-charcoal ≈ 5.2:1), so compute the pair instead of pattern-matching 'dark hero → white button'.
- **A mock's essential surface must live on its own class,** never only on a wrapper-descendant selector (`.tile-mock .phone-ui { background }`). Redesigns drop wrappers; the descendant rule dies with them and the component renders white-on-white invisible. After markup changes, check computed `backgroundColor`/`color` of dark-surface mocks, not just that the class exists.
- **CSS purge regexes match substrings.** A removal pattern for `.p-num` also eats `.p-num .p-scale` and freshly re-added rules; line-anchored patterns miss descendant selectors (`.parent .child`) and compound selector groups. After any CSS surgery, verify the result with computed styles — source greps cannot see what the cascade actually applies. Removing a wrapper `<div>` also requires removing its matching close tag — assert open/close balance per section.
- **Lazy images false-report broken.** `naturalWidth===0` on below-fold `loading="lazy"` images is the no-scroll artifact, not a bug — scroll the page first, then assert. When a page has few images, drop lazy entirely so full-page screenshots (the user's defense artifacts) never capture blanks.
- **Long unbroken strings (emails, URLs) blow out grid cells.** `overflow-wrap: break-word` does NOT reduce min-content; use `overflow-wrap: anywhere` on the string + `min-width: 0` on grid/flex children. Diagnose with a leaf-overflow query (`scrollWidth > clientWidth` walk) before touching CSS.
- **Vision findings need DOM adjudication** for load-state questions (gray box vs failed image) — screenshot passes do not trigger lazy loads.
- **Meta/OG tag content is exempt** from visible-copy sweeps; strip comments before grepping so review-note text does not false-positive.
- **Client-side data overlays persist between Playwright runs.** Prototype admin CRUD backed by a localStorage store survives in the default browser profile, so an E2E run can assert against a prior session's edited dataset instead of the shipped one (stale counts, phantom rows, masked regressions). Launch a fresh context with `addInitScript(() => localStorage.clear())` before any dataset-count or render assertion, and never trust a "clean" first-pass E2E that silently ran on modified data.

## Parallel build pattern (multi-page sites)
Dispatch 2 subagents with DISJOINT file ownership (agent A: index + shared css/docs; agent B: the other pages), each told 'YOU OWN exactly: ... DO NOT touch: ...'. Same working tree, no conflicts. Steer running children for mid-flight directives. On return: verify independently (own greps/screenshots) — child reports are self-reports.

When delegating vision audits, require geometry cross-checks: every flag must be verified against DOM computed styles/rects before it is reported (this rejects most vision hallucinations — invented buttons, phantom telemetry, artifact collisions). State the design intent in the brief so auditors judge execution, not direction; in final-polish mode explicitly instruct them not to recommend adding content or sections.
