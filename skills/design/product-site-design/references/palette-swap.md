# Palette / identity swap procedure (recolor without renaming variables)

Class: replacing a site's color identity (e.g. cobalt → warm indigo + coral + cream) while keeping every class and selector stable. The failure modes are broken `var()` references, surviving old-hex literals in non-CSS files, rainbow category tints, and contrast regressions discovered after deploy.

## Procedure
1. **Contrast-check the target palette BEFORE writing CSS.** Compute WCAG ratios for every pair that will ship: primary-on-white, text-on-hero, tag-ink-on-soft-tag, accent-button-on-hero. Fix values in the spec stage (darken a text ink, not after screenshots). Node one-liner with the luminance/ratio functions ships this check in ~10 lines; run it on the spec table first.
2. **Swap values inside the existing token names; keep old names as aliases.** `--accent: var(--primary)` etc. so every existing `var()` resolves. Never rename tokens during a recolor — that is a second bug in every consumer.
3. **Prove token coverage programmatically:** concatenate all CSS, collect `--defined` names vs `var(--used)` names, assert none missing. This catches aliases a rename silently dropped.
4. **Purge old literals tree-wide, not just stylesheets.** Old hex codes survive in: SVG `fill=`/`stroke=` (logo, icons), URL-encoded inline favicons (`%23` prefix), JS chart color arrays, admin/login page inline SVGs, hover shades. Grep the whole tree for each old hex case-insensitively; re-shoot until zero.
5. **Charts: one brand hue ramp + a single accent slice.** A different strong hue per category reintroduces the six-mini-brands problem inside the one place data is densest.
6. **Category tints: one family.** Derive all category soft backgrounds from the two accent families (e.g. a lavender ramp ↔ a coral-cream ramp) with matching line/ink variants. Cards must read as one product, not one brand per category.
7. **Semantic colors keep their own roles.** Ratings/stars get the universally-expected warm gold (icon-size contrast ≥3:1), not the brand accent — the accent stays reserved for featured/CTA moments. Success/warning/danger never double as brand hues.
8. **Unify dark surfaces to ONE family.** Hero, CTA band, footer, compare tray, admin sidebar must share the same dark values (or explicit lightness steps of it). Three 'close but different' dark purples read as drift, and a leftover near-black `--ink` surface reads off-palette in every screenshot.
9. **Re-verify with computed styles, then screenshots.** Probe `getComputedStyle` on the hero panel, buttons, tray, footer (backgroundColor/text color pairs), then shoot desktop + mobile and AA-check what actually renders.
10. **Hero copy follows the same discipline as the palette: one focal metric, not a report.** The hero showcase earns image + name + price + ONE score. Spec rows, quotes, formulas, methodology, and badges belong on the product detail page; 'the hero is for impact, the detail page is for depth.' A de-composed hero also needs an editorial rhythm to land: replace card-grid feature sections with large typographic heads ('₱ / month', 'Repairability') over small quiet copy, demote secondary features (charts, step bands) to smaller headings with hairline separators, and strip step-band copy down to number + word. Repetition between sections (the same top-3 in two formats) is drift the swap creates or exposes — resolve to one.
11. **Deterministic-explanation products keep scoring arithmetic visible and single-vocabulary.** One score name everywhere ('Ownership Index', not alternating with 'monthly ownership'), metric-based explanations only (breakdown tables, weights, ranks — never AI prose), thresholds phrased honestly ('Under your budget at ₱9,499' when the price is below the band floor), and no fabricated precision beyond what the formula emits.

## Pitfalls
- **Near-black tokens hide inside 'neutral' roles.** A `--ink`-background footer or fixed tray survives a hue swap untouched and becomes the only black element on the page. During any identity swap, enumerate every surface using the ink/near-black token and decide: dark-family member or real neutral.
- **Image hosts are part of the data audit.** After any catalog touching, HEAD-check EVERY image URL on the exact host stored in the data (some CDN thumb hosts 404 intermittently while the `upload` host 200s) and normalize to one host; assert `200 image/*` for all, and assert no duplicate URLs (two products sharing an image is a copy-paste bug that survived spot checks). Extend the check to borrowed-image semantics: search the Commons API per product NAME, not per category — a category-level search returns an unrelated device (an iPhone photo for a POCO) that the 200-check cannot catch; a vision pass catches what curl cannot.
- **Multi-retheme projects accumulate dead rules from previous identities.** When a hero card is later replaced by a showcase composition, its dedicated rules (`.value-tag-feature`, `.vt-score`, `.vt-quote`) survive as dead weight. After structural hero/section rebuilds, grep for the old component's class names and delete their rule blocks — and re-check section order: a 'supporting feature' section (chart) may need demotion below the product-proof sections it used to lead.
- **Section-copy drift after structural edits.** When a redesign removes or merges a section, grep the surviving copy for positional/spatial wording ('on the left', 'Coral dots', a removed column's name) — stale references to the OLD structure are copy bugs, not styling ones, and survive every visual diff because the words still parse.
- **Category-tint tokens need per-key ink/line fixes, not just hue swaps.** A literal old→new hex map recolors category SOFT backgrounds but leaves per-category INK values stale — a violet ink under a blue soft, a green icon chip breaking the one-brand rule. After the swap, audit each category's tint/soft/line/ink quadruple against the spec; the ink is what the eye reads as brand.
