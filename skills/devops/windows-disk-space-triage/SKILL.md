# Windows Disk Space Triage

## Fast path: WizTree CLI (MFT = seconds)

WizTree (free, MFT-based) is installed at `C:\Program Files\WizTree\WizTree64.exe`. Correct syntax — **drive path FIRST, export flags are 0|1**:

```
"/c/Program Files/WizTree/WizTree64.exe" 'C:\' '/export=C:\Users\<user>\AppData\Local\Temp\wiztree.csv' /admin=1 /exportfolders=1 /exportfiles=1
```

Run with background=true + notify_on_complete, then poll for the CSV (full ~500GB drive ≈ 800MB CSV, ~5M rows).

Pitfalls (all hit in the field — each one silently produces nothing):
- Wrong syntax does NOTHING with exit 0: missing positional drive arg, `/exportfolders=<path>` (it's `=0|1`), or no `/export=`.
- `/admin=1` pops a UAC prompt the user must click Yes; `/admin=0` skips UAC but falls back to a slow non-MFT scan (5+ min, looks hung).
- `/admin=1` spawns an **elevated child**: the parent exits immediately, so `&& echo DONE` fires before the scan finishes. The child also holds the CSV with an exclusive lock — reading it from a non-elevated shell gives `PermissionError` / `Device or resource busy`. Wait until WizTree64.exe leaves `tasklist`, then read.
- `taskkill` from a non-elevated shell CANNOT kill the elevated child — just wait; it exits on its own.
- Parse with Python `csv` module (quoted paths), not awk.

## Parse the CSV

Layout: banner line (`Generated by WizTree ...`), then header `File Name,Size,Allocated,Modified,Attributes,Files,Folders,DRIVECAPACITY,...`.
- name = col 1 (quoted), **size = col 2** (bytes), modified = col 4, format `2026 08 01 21:46:13`
- Directory rows = name **ends with backslash** (attribute column is inconsistent: 2/6/16 — don't trust it)
- Reusable parser: `scripts/wizparse.py <export.csv> [min_date=YYYYMMDD]` → top-level dirs, biggest 45 files, recent big files.

## Fallback: robocopy /L (no WizTree installed)

```
robocopy /L /E /MT:32 /NJH /NJS /NDL /NC /BYTES /FP /R:0 /W:0 'C:\' 'C:\Users\<user>\AppData\Local\Temp\nulscan' /XD 'C:\Windows' ...
```
- Dest dir MUST exist or robocopy prints usage and exits (the /L listing needs a valid dest).
- Slow on drives with millions of small files — prefer WizTree.

## Windows git-bash pitfalls

- `du`/`find` on user dirs with node_modules/caches times out (120-300s+). Skip them; WizTree walks the MFT in seconds.
- PowerShell one-liners in double quotes: bash eats `$_` (e.g. `$_.Free` becomes a path). Wrap the whole `-Command` in single quotes.
- `python /c/Users/.../script.py` → python resolves `C:\c\Users\...`; use `python "C:/Users/.../script.py"`.
- Python heredocs (`<<'EOF'`) mangle backslashes (`'\\'` becomes unterminated string). Write the script with write_file instead.

## Space-hog checklist (check these in the export first)

- `pagefile.sys` at C:\ root (system-managed grows to 10-20GB; cap it if needed), `hiberfil.sys`
- `C:\WINDOWS\SoftwareDistribution\Download` — Windows Update cache; single update can be 9GB+; safe to wipe with wuauserv stopped
- `C:\WINDOWS\Installer` (30GB+ lifetime cruft, don't delete blind), `WinSxS` (DISM /StartComponentCleanup)
- `C:\WINDOWS\System32\DriverStore\FileRepository` — old GPU driver packages kept after each driver update (pnputil /enum-drivers)
- **Ollama**: `ollama list` shows models, but with an OLLAMA_MODELS override the blobs can live ANYWHERE — on this PC: `C:\Users\YOUR_USERNAME\blobs` (23GB of sha256-* GGUF blobs), not `~/.ollama/models`
- Caches: `npm cache clean --force` (can be 10GB+), %TEMP%, Android Studio `system-images` (single 8GB system.img), Downloads installers (WebStorm/Android Studio .exe linger)
- Games folders in Documents are usually just save files (KBs) — don't chase them; real installs live elsewhere.

## Report format

Give a table: item | size | when | what it is. Then offer cleanup split into "safe, no admin" vs "needs UAC". Never delete anything without asking first.
